RemoteControl v0.4.5 설치 매뉴얼

작성일: 2026-10-10 · Android Host/Target + Ubuntu 중계서버

1. 배포 파일과 준비 사항

  • RemoteControl-host-v0.4.5.apk: 조작하는 스마트폰용, 패키지 com.remotecontrol.host.
  • RemoteControl-target-v0.4.5.apk: 화면을 제공하는 스마트폰/갤럭시탭용, 패키지 com.remotecontrol.target.
  • RemoteControl-server-v0.4.5.tar.gz: Ubuntu용 서버 설치 묶음. 압축을 풀면 server/ 생성.
  • server/: 같은 서버 묶음의 압축 해제본. Python 표준 라이브러리만 사용하며 pip 의존성 없음.
  • SHA256SUMS.txt: 패키지 파일 무결성 확인용.

앱은 현재 프로젝트의 Debug 서명 APK입니다. release는 전달 폴더 이름이며 Play Store용 정식 Release 서명본이라는 뜻이 아닙니다. 버전명 0.4.5, 버전 코드 9, Android 8.0(API 26) 이상입니다. 휴대폰과 태블릿, Wi-Fi 전용 기기에서 사용 가능합니다. 모든 제조사/OS 조합에서 실기기 검증된 것은 아닙니다.

서버는 Ubuntu 20.04 이상, Python 3.8 이상, systemd, sudo 권한, 외부에서 접근 가능한 IP가 필요합니다. 새 설치 스크립트는 Ubuntu 버전과 systemd를 확인합니다. 향후 Ubuntu 버전까지 실제 실행을 보장하는 것은 아니며 해당 서버에서 설치 후 점검해야 합니다. OS 보안 업데이트와 유지보수는 운영자가 수행합니다.

서버를 가리키는 도메인(이하 relay.example.com)과 Android가 신뢰하는 공인 CA 인증서가 필요합니다. 예시 도메인과 경로는 실제 값으로 바꾸세요. 서버 접속 포트는 TCP 55000~60000 중 하나이며 기본값은 55000입니다. 모든 범위를 열 필요는 없습니다. HTTP reverse proxy가 아닌 TCP/TLS 서비스입니다.

2. 새 Ubuntu 서버 준비

서버에 배포용 tar.gz를 복사한 후 실행합니다.

sudo apt-get update
sudo apt-get install -y python3 ca-certificates openssl tar
mkdir -p ~/remotecontrol-install
cd ~/remotecontrol-install
# 이 폴더에 RemoteControl-server-v0.4.5.tar.gz를 복사한 다음:
tar -xzf RemoteControl-server-v0.4.5.tar.gz
cd server
python3 -m unittest -v test_relay

이미 전체 release 폴더를 복사했다면 그 안의 server로 이동하면 됩니다. SHA256 파일이 포함된 전체 패키지는 release 루트에서 sha256sum -c SHA256SUMS.txt로 확인할 수 있습니다.

3. TLS 인증서 준비

기존 공인 인증서가 있으면 fullchain PEM과 암호 없는 개인키 PEM 경로를 준비하고 4단계로 이동합니다. 개인키나 서버 접속 키는 GitHub에 올리지 않습니다. 자체 서명 인증서 또는 도메인이 맞지 않는 인증서는 앱에서 거부됩니다. 숫자 IP로 접속하려면 그 IP가 SAN에 포함된 신뢰 가능한 인증서가 별도로 필요하므로 일반적으로 도메인을 사용하세요.

새 도메인에 Let's Encrypt 인증서를 발급하는 예시입니다. DNS A 레코드가 서버 공인 IPv4를 가리켜야 합니다. AAAA 레코드가 있다면 IPv6로도 올바른 서버에 도달해야 합니다. standalone 발급 시 TCP 80이 외부에서 접근 가능하고 다른 웹서버가 점유하지 않아야 합니다. 이미 웹서버가 운영 중이면 기존 인증서를 사용하거나 Certbot의 webroot/DNS 방식을 선택하세요.

sudo apt-get install -y certbot
sudo certbot certonly --standalone -d relay.example.com

성공하면 일반적으로 다음 파일이 생성됩니다. 실제 Certbot 출력 경로를 확인하세요.

/etc/letsencrypt/live/relay.example.com/fullchain.pem
/etc/letsencrypt/live/relay.example.com/privkey.pem

Certbot 공식 안내: https://certbot.eff.org/instructions

Ubuntu Certbot 설명: https://manpages.ubuntu.com/manpages/noble/man1/letsencrypt.1.html

4. 서버 최초 설치

압축을 푼 server 폴더에서 실행하세요.

sudo python3 install-server.py   --cert /etc/letsencrypt/live/relay.example.com/fullchain.pem   --key /etc/letsencrypt/live/relay.example.com/privkey.pem   --port 55000

스크립트는 인증서/개인키 짝을 검사하고 전용 계정, 서비스, 새 무작위 64자리 서버 접속 키를 만듭니다. 인증서의 공개 신뢰 여부·도메인·유효기간까지 검증하는 것은 아니므로 아래 연결 점검을 수행하세요. 재부팅 후 서버 서비스는 자동 시작됩니다. 기존 설치 경로가 있으면 덮어쓰지 않고 중단합니다.

항목설치 위치
서버 프로그램/opt/remotecontrol/relay.py
인증서 / 개인키/etc/remotecontrol/fullchain.pem, privkey.pem
접속 키/etc/remotecontrol/access.key
systemd 서비스/etc/systemd/system/remotecontrol-relay.service
sudo systemctl status remotecontrol-relay --no-pager
sudo journalctl -u remotecontrol-relay -n 100 --no-pager
sudo ss -ltnp | grep ':55000'
sudo cat /etc/remotecontrol/access.key

마지막 명령의 64자리 키를 허용할 Host와 Target에 동일하게 입력합니다. 이 키를 아는 사용자는 서버의 모든 Target 목록을 볼 수 있고, 공유 승인된 Target에 연결할 수 있습니다. 사용자별 계정이나 기기별 권한 분리는 없습니다.

서버 방화벽, 클라우드 보안 그룹, 공유기 NAT 포트 전달에서 선택한 TCP 포트를 허용하세요. UFW가 이미 활성화되어 있다면 다음처럼 규칙을 추가합니다. 설치 스크립트는 방화벽이나 SSH 설정을 변경하지 않습니다.

sudo ufw allow 55000/tcp

다른 PC 또는 서버에서 TLS를 점검합니다.

openssl s_client -connect relay.example.com:55000   -servername relay.example.com -verify_hostname relay.example.com   -verify_return_error </dev/null

인증서 검증 성공을 확인하세요. 이 명령은 앱 프로토콜 인증을 보내지 않으므로 서버가 이후 연결을 닫는 것은 정상입니다. TCP 접속 자체가 실패하면 DNS/방화벽/포트 전달을 확인합니다.

5. 스마트폰과 갤럭시탭 설치

  1. 조작할 폰에 Host APK, 화면을 제공할 폰/탭에 Target APK를 복사합니다.
  2. 기기의 파일 관리자에서 APK를 실행합니다. 필요하면 해당 파일 관리자에 대한 ‘출처를 알 수 없는 앱 설치’를 허용합니다. 제조사 정책에 따라 추가 설치 확인이 나올 수 있습니다.
  3. 기존 앱과 서명이 같으면 업데이트 설치합니다. ‘패키지가 충돌’하거나 서명이 다르면 기존 앱 데이터/키를 먼저 보관하고 기존 앱을 삭제한 후 설치해야 합니다. 삭제하면 앱 내부 설정과 로그가 사라집니다.
  4. 두 앱의 제목에 v0.4.5가 표시되는지 확인합니다. 한쪽만 업데이트하지 마세요.
  5. 앱에 미리 표시되는 예전 서버 주소를 새 서버의 relay.example.com:55000으로 반드시 변경합니다. https://를 붙이지 않습니다.
  6. 두 앱에 4단계에서 확인한 새 서버 접속 키를 입력합니다. 예전 서버의 키 파일을 불러오면 새 서버에 인증되지 않습니다.
  7. Target에 식별하기 쉬운 기기 이름을 입력하고 알림 권한을 허용합니다.
  8. 원격 터치도 필요하면 Target에서 ‘터치 제어 권한 설정’을 눌러 Android 접근성 설정의 RemoteControl 터치 제어를 켭니다. 보기 전용이면 필요하지 않습니다.

Android 13 이상에서 접근성 설정이 제한된 경우, 신뢰하는 이 APK의 앱 정보 화면에서 ‘제한된 설정 허용’ 메뉴가 제공되는지 확인한 뒤 직접 승인하세요. 메뉴 위치와 제공 여부는 제조사에 따라 다릅니다. 공식 안내: https://support.google.com/android/answer/12623953?hl=ko

갤럭시 기기에서 화면 꺼짐 후 연결이 끊기면 앱 배터리 제한/절전 앱 설정을 확인하세요. 설정 변경만으로 상시 접속이 보장되지는 않습니다. Host의 화면 유지 옵션은 이미 연결된 공유 세션에서만 작동합니다.

6. 설치 완료 확인

  1. Target에서 ‘서버 연결 / 자동 재접속 시작’을 누릅니다.
  2. Host에서 ‘서버 연결 / 목록 새로고침’을 눌러 Target 이름이 보이는지 확인합니다.
  3. Target에서 ‘화면 공유 시작’을 누르고 시스템 공유 창을 승인합니다.
  4. Host 목록에서 ‘연결 가능’인 Target을 선택하여 화면이 표시되는지 확인합니다.
  5. 터치 허용 상태라면 뒤로/홈/터치를 확인합니다.
  6. Host의 ‘연결 중 Target 화면 켜짐 유지’를 켜고 Target 자동 화면 꺼짐 시간을 지나도 유지되는지 확인합니다. 옵션을 끄거나 연결을 종료한 후 자동 꺼짐이 복원되는지도 확인합니다.

7. 다른 서버로 이전

새 서버에는 위 최초 설치 절차를 수행하세요. 기본적으로 새로운 접속 키가 생성됩니다. 앱에서 기존 연결/공유를 종료하고 새 주소와 새 키를 입력한 후 Target을 다시 연결하고 공유 승인합니다. Target 앱을 새 기기에 설치하면 새 기기 ID로 등록됩니다. 기존 기기를 끄지 않으면 두 기기가 각각 목록에 보일 수 있으므로 이름을 구분하세요.

기존 키를 유지해야 하는 경우 운영자가 안전한 경로로 /etc/remotecontrol/access.key를 새 서버에 복사하고 root:remotecontrol, 권한 640을 적용한 뒤 서비스를 재시작합니다. 인증서는 새 접속 도메인과 일치해야 합니다. 접속 키는 인증서 개인키와 서로 다른 파일입니다. 새 서버 정상 동작 확인 후 기존 서버 서비스를 중지하세요.

8. 기존 서버 프로그램 업데이트

이 패키지의 server 폴더에서 실행합니다. 표준 경로로 설치된 서비스가 있어야 합니다.

sudo sh update-server.sh

현재 프로그램을 백업하고 새 relay.py를 설치한 뒤 서비스를 재시작합니다. 기존 키·인증서·서비스 포트 설정은 유지합니다. 진행 중인 원격 연결은 종료됩니다. Host에서 다시 연결하세요. 포트를 변경하려면 sudo systemctl edit --full remotecontrol-relay로 ExecStart의 포트를 바꾸고 daemon-reload 및 restart 후 방화벽과 두 앱 주소를 함께 바꾸세요.

9. 인증서 갱신과 서비스 관리

이 서비스는 인증서 복사본을 사용하므로 Certbot 원본만 갱신하면 서비스에 반영되지 않습니다. 갱신 후 설치 묶음의 server 폴더에서 실행하세요.

sudo certbot renew
sudo python3 install-server.py --refresh-certificate   --cert /etc/letsencrypt/live/relay.example.com/fullchain.pem   --key /etc/letsencrypt/live/relay.example.com/privkey.pem

기존 인증서는 /etc/remotecontrol/*.previous로 1회 백업하고 검증한 새 파일을 복사한 뒤 재시작합니다. Certbot 자동 갱신에는 위 refresh 명령을 실제 설치 스크립트의 절대 경로로 호출하는 deploy-hook을 별도로 등록하세요. 이 패키지는 갱신 예약이나 hook을 자동 등록하지 않습니다. sudo certbot renew --dry-run으로 인증서 갱신 조건을 확인하세요. standalone 방식이면 이후 갱신 때도 80번 접근이 필요합니다.

sudo systemctl restart remotecontrol-relay
sudo systemctl stop remotecontrol-relay
sudo systemctl start remotecontrol-relay
sudo journalctl -u remotecontrol-relay -f

설치 중 오류가 발생하면 메시지와 journalctl을 먼저 확인하세요. 부분 설치 경로를 무작정 삭제하지 마세요. 프로그램 설치와 서비스 파일 생성까지 끝났다면 원인을 수정하고 systemctl restart로 다시 시작할 수 있습니다. 사용자/권한/인증서 준비 단계에서 실패했다면 생성된 파일을 검토하여 복구해야 합니다. 자동 롤백은 제공하지 않습니다.

10. 검증 범위

패키지 제작 시 APK 서명·버전·체크섬, 앱 단위 테스트/lint 결과, 서버 프로토콜 테스트 및 설치 스크립트 구문을 확인합니다. 이 Windows 작업 환경에서 Ubuntu systemd 최초 설치와 갤럭시탭 실제 화면 유지 시험은 수행하지 않았습니다. 위 설치 완료 확인을 실제 배포 환경에서 수행하세요.
