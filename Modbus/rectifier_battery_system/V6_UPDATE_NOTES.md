# V6 모니터링 개선

실행: `python LCD_GUI_Pannel_Master_modbus_V6.py`

연결 전에 COM, Baud, **설치 모듈 수(Auto 또는 1~10)**를 설정합니다. 기본값인 Auto는 연결 시 1~10번 전체에 배터리 조회를 보내 정상 응답한 모듈만 감시합니다. 번호가 연속되지 않아도 지원하며, 검출 수와 번호를 연결 상태에 표시합니다. 검출 이후 통신이 끊긴 모듈은 감시 대상에 유지하고 재시도합니다. 최초 검색에 응답하지 않은 모듈을 다시 검색하려면 연결을 해제한 뒤 다시 연결하세요. 숫자를 직접 선택하면 기존처럼 1번부터 선택한 수까지 감시합니다. 표의 행 또는 모듈 버튼을 선택하면 해당 모듈의 셀 및 바코드를 확인할 수 있습니다.

## 변경 사항

- 배터리 조회: 모듈당 80 → 54개 레지스터. 마지막 사용 주소인 SOH까지 읽고, 모듈 간 64개 주소 간격을 넘지 않습니다. 기존 주소·부호·단위 변환은 유지했습니다.
- pySerial로 송수신 경로를 통합했습니다. 응답 길이만큼 도착하면 처리하며 Slave ID, function, byte count, CRC를 검증합니다. 분할 수신·잡음·예외 응답을 처리하고 송신 제한시간과 baud별 응답 제한시간을 적용했습니다.
- RTU 프레임 사이 대기와 오류 후 늦은 응답 폐기를 적용했습니다. RTU 응답에는 요청 주소/거래 ID가 없으므로, 장비가 제한시간을 크게 초과해 응답하는 경우 현장 TX/RX 로그로 지연 특성을 확인해야 합니다.
- 배터리를 먼저 전체 조회한 뒤 보조 정보를 읽습니다. 시간·전체 알람은 약 5초 간격, 상세 알람은 매 순회 한 모듈씩 돌아가며 최소 5초 간격으로 조회합니다. 실제 간격은 모듈 수와 통신 시간에 따라 길어집니다. 오래된 알람은 지연 상태로 표시합니다.
- 상세 알람 13개를 블록으로 읽습니다. 조회 실패나 대기 상태를 정상으로 표시하지 않습니다.
- 바코드는 연결 세션 중 모듈별로 캐시합니다. 조회 실패 시 30초 후 재조회하며, 배터리 통신 실패 시 해당 바코드 캐시를 무효화합니다.
- 배터리 조회 실패 모듈은 3초 후 재시도합니다. GUI에는 마지막 수신 값과 실패/지연 상태 및 수신 경과 시간을 표시합니다.
- 10대 비교표, 첫 수신 모듈 자동 선택, 모듈별 바코드, 실제 수신 기준 경과 시간, 전체 순회 소요시간을 추가했습니다.
- 연결/종료 시 GUI 대기 및 중복 스레드 시작을 제거했습니다. 종료 완료 신호 후 스레드를 정리합니다.
- CSV는 선택 여부와 관계없이 수신 모듈의 배터리·셀을 함께 기록합니다. 셀 전압 파싱 및 잘못된 함수 인자를 수정하고, 모듈 선택 시 중복 기록을 방지했습니다. 알람은 가장 최근 조회 결과이므로 배터리와 수집 시점이 다릅니다.

## 검증

`python -m unittest test_modbus_v6 -v`

16개 오프라인 테스트: CRC 기준값, 분할 수신, 잡음/다른 Slave/CRC 오류, 응답 길이 오류, 잘린 응답, Modbus 예외, 취소, 모듈 10 주소 및 음수 값, 바코드 캐시, 알람 실패, 재시도 간격, 10대 GUI 전환, CSV, 재연결 초기화, 연결 실패, 스레드 종료.

`v6_gui_preview.png`는 실제 측정값이 아닌 10대 모의 데이터 화면입니다.

실제 장비에 연결하거나 성능을 실측하지 않았습니다. 현장에서는 설치 수를 맞춘 뒤 Scan 시간, 모듈별 수신 경과, 알람/셀 데이터 및 TX/RX 로그를 확인해야 합니다. 특히 기존 프로토콜의 단위 변환과 연속 레지스터 읽기 지원은 장비 명세와 대조가 필요합니다.

송수신 API 참고: [pySerial 공식 문서](https://pyserial.readthedocs.io/en/latest/pyserial_api.html).
