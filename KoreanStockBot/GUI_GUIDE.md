# ETF·단일 종목 GUI 사용법

세 실행 파일 모두 다크 테마 GUI를 엽니다. `start.bat`는 모의매매, `start_etf.bat`는 ETF 자동 선정·주문, `start_live.bat`는 지정한 단일 종목 주문입니다.

## 진단 로그와 문의용 파일 (v1.0.22)

1. 화면 하단의 **진단 로그 파일 생성**에 체크합니다. 기본값은 꺼짐이며 선택 상태는 다음 실행에도 유지됩니다.
2. 문제가 생기는 계좌 조회, 후보 조회, 읽기 전용 점검 등의 동작을 실행합니다.
3. **공유용 진단 ZIP 저장**을 누릅니다. 이 ZIP을 대화에 첨부하고 누른 버튼·기대한 결과·발생 시각을 알려주세요.

ZIP의 `먼저읽기_진단요약.txt`에서 이번 실행의 마지막 상태를, `진단기록_0.txt`에서 시간순 진행을 확인하세요. `수집상세_최근기록.txt`는 기존 기본 수집 기록에서 필요한 필드만 추출하므로 이전 실행도 포함될 수 있습니다.

로그는 실행 폴더의 `logs`에 UTF-8 한글 텍스트로 저장합니다. 버전, 한국시간, API 처리 단계와 응답 시간, 성공/실패 코드, 처리 개수, 설정 금액, 주문 신호·제출 응답과 중지 확인을 기록합니다. 주문 제출 응답은 체결 확정이 아닙니다. 인증키·계좌번호/계좌 선택값·주문 ID·환경변수·원본 API 응답은 기록하거나 ZIP에 넣지 않습니다.

체크를 해제하면 추가 진단 기록을 중단하며 이미 생성된 파일은 유지합니다. 거래 복구용 상태와 기본 수집 감사 기록은 별도 유지됩니다. 로그가 꺼져 있던 구간은 복원할 수 없습니다. 프로그램이 비정상 종료되면 `logs`의 해당 시각 TXT를 직접 첨부할 수 있습니다. 공유 ZIP은 현재 실행 세션의 진단 기록을 담습니다.

## 실행 순서

### 하단 우측 상태 안내 (v1.0.24)

스크롤을 내려도 창 하단 우측에 상태와 다음 행동이 표시됩니다. 파랑은 진행 중이므로 기다리기, 노랑은 응답 지연 또는 자료 확인 필요, 빨강은 중지 요청/중단/오류, 초록은 자료 수집 완료입니다. 색과 함께 표시되는 문구로 '요청에 따른 중단'과 '문제 발생'을 구분하세요.

첫 수집은 **첫 수집 진행 중—분석 완료 대기**로 표시합니다. 재무·뉴스 완료 숫자가 증가하면 기다려 주세요. 초록색 완료는 자료 생성 완료이며 모든 ETF의 매수 조건 통과를 뜻하지 않습니다. 개별 ETF 구성정보 제외는 전체 수집 실패와 구분합니다.

KRX 구성정보 검증 실패는 ETF 종목코드, 오류 분류, 관측 비중과 허용 범위를 수집 상태·로그·공유 ZIP에 기록합니다. 종목 비중 검증 기준을 자동 완화하지 않습니다.

### 설정 파일 사용

1. 인증·계좌 설정 창의 **설정 템플릿 생성**으로 빈 JSON 파일을 저장합니다.
2. 메모장으로 `credentials`의 따옴표 안에 키를 입력하고 저장합니다. `format`, `version`, 항목 이름은 그대로 둡니다. 계좌 선택값은 비워 둬도 되며, `symbol`은 단일 종목 코드(ETF는 빈 값)입니다. 비밀번호에 따옴표나 역슬래시가 있으면 JSON 규칙에 맞게 이스케이프해야 합니다.
3. **템플릿 암호화 변환**에서 작성한 JSON을 선택하고 `.ksbkey`로 저장합니다. 변환 후 평문 원본 삭제 여부를 선택합니다.
4. **설정 파일 불러오기**에서 `.ksbkey`를 선택합니다. **계좌 조회 → 선택 → 암호화 저장**으로 적용합니다.

암호화는 Windows DPAPI를 사용하며 같은 PC·동일 Windows 사용자에서 복호화합니다. 해당 사용자 권한으로 실행되는 프로그램까지 차단하는 방식은 아닙니다. 다른 PC로 옮기는 휴대용 비밀번호 암호화가 아닙니다. 평문 원본이나 클라우드·백업 사본은 별도로 관리해야 합니다. 파일 변환·불러오기는 주문을 실행하지 않습니다.

1. 최초 `install_auto.bat`로 설치하고 원하는 실행 파일을 엽니다.
2. **인증·계좌 설정**에서 토스 인증값을 입력합니다. ETF에는 KRX·DART·NAVER API HUB 인증도 입력합니다. 네이버 클라우드 콘솔에서 API HUB의 News 권한을 선택해 발급한 Client ID·Secret을 사용합니다. 기존 개발자센터 키를 저장했다면 새 값으로 바꿔 암호화 저장하세요. 이용 요금·사용량 한도도 확인합니다.
3. **계좌 조회** 후 목록에서 계좌를 선택합니다. 하나면 자동 선택되고, 여러 개면 직접 선택합니다. 토스 인증정보 변경 시 다시 조회하세요. 단일 종목은 종목코드도 입력합니다.
   키·비밀번호 옆 **👁 보기 / 숨기기**로 입력값을 확인할 수 있습니다. 창을 다시 열면 숨김 상태입니다. 앞뒤 공백·탭·줄바꿈은 조회와 저장 시 자동으로 제거되며, 값 내부의 문자는 유지됩니다.
4. **암호화 저장**을 누릅니다. 같은 Windows 사용자 DPAPI 저장소를 사용하며 기존 콘솔에서 저장한 값도 불러옵니다.
5. **읽기 전용 점검**으로 계좌·분석·시세를 확인합니다. 주문을 제출하지 않는 점검이며 가상 체결 시뮬레이션은 아닙니다.
6. **중지 요청** 후 프로세스 종료를 확인합니다.
7. **실전 시작**을 누르고 실제 주문 확인창을 승인하면 자동 주문을 시작합니다. STOP 파일이 남아 있으면 기존 주문 확인 후 해제 여부를 묻습니다.

창만 열어서는 주문하지 않습니다. 한 폴더에서는 ETF·단일 종목·읽기 전용 점검 중 하나만 실행할 수 있습니다. 실전 기록이 있는 단일 종목의 코드는 GUI에서 변경하지 못합니다.

## 상태와 그래프

### 수집 로그 파일

자동 분석을 실행하면 실행파일 폴더의 `research/logs/collection.log`에 UTF-8 JSON 형식으로 한 줄씩 기록합니다. 메모장으로 열 수 있습니다. 2MB를 넘으면 `.1`~`.5` 백업으로 순환합니다.

- `run_id`: 같은 자동 수집 작업을 구분하는 ID. `time`: 한국시간.
- `START` / `COMPLETED` / `FAILED`: 단계 시작 / 완료 / 실패. `SOURCE_RESULT`: API 수신 또는 캐시 사용.
- `KRX_ETF_DAILY`, `KRX_ETF_METADATA`, `KRX_COMPOSITION_REQUEST`: ETF 목록·기본정보·구성정보.
- `DART_CORPORATION_MAP`, `DART_FINANCIAL_REQUEST`, `DART_FINANCIAL_ANALYSIS`: 기업코드·재무 요청·재무 분석.
- `NAVER_NEWS_REQUEST`, `NAVER_NEWS_ANALYSIS`: 뉴스 요청·분석.
- `HTTP_ERROR`는 `http_status` 숫자를 함께 확인합니다. 인증·권한, 호출 제한, 서버 장애는 코드와 실행 상황을 함께 확인해야 하며 모든 오류가 키 오류인 것은 아닙니다.
- `NETWORK_OR_TIMEOUT`: 통신 또는 시간 초과. `MISSING_*`: 필수 인증값 없음. `INVALID_*`: 응답 형식 오류. `VALIDATION_OR_LOCAL_ERROR`: 데이터 검증 또는 파일 등 로컬 오류.

상태 창의 `NOT_REQUESTED`는 아직 요청하지 않았다는 뜻입니다. 전체 수집이 실패했다면 앞 단계가 중단되어 도달하지 못했음을 표시합니다. 키·비밀번호·요청 URL·HTTP 헤더·서버 응답 본문·원문 예외 문자열은 로그에 저장하지 않습니다.

- **ETF 후보 제안**은 순자산 상위 20개 중 중복 없는 실제 종목을 제시합니다. 중지 완료 후 열면 계좌·시세를 읽기 전용으로 조회하고 자동 수집된 재무·뉴스와 추세를 확인합니다. 조건 통과 종목을 클릭해 선택/해제하고 적용한 뒤 다시 시작하세요. 실행 중에는 기존 분석 결과만 표시합니다.
- 현재가, 1주 필요액(현재가 × 1.01 + 10원), 예산 내 추정 주수, 재무점수, 추세, 제외 사유를 표시합니다. 예산은 계좌 원화 주문 가능액·봇 현금·투자 비중·주문 상한 중 최솟값입니다. 예산 내 주수는 최종 주문 수량이 아닙니다.
- 선택 종목 중 한 번에 한 종목을 운용하며 매수 전 최신 순위·가격·호가·위험 조건을 재검사합니다. 기존 보유분의 매도 조건은 유지됩니다. 5분이 지난 분석은 다시 조회해야 적용할 수 있습니다. 후보가 없으면 조건을 자동 완화하지 않고 대기를 제안합니다. 조회 실패 시 읽기 전용 점검으로 자료 수집 상태를 확인하세요. 장외 시세가 오래되면 추천되지 않을 수 있습니다.
- 범위는 해당 계좌·설정에 연결해 runtime/etf_scope.json에 저장하며, 기존 운용 장부와 보유분의 매도 조건은 바꾸지 않습니다.

- ETF 매수 대기 시 선별 예산과 종목별 제외 사유를 수치로 표시합니다. 상태 영역은 일부 종목을 요약하고 아래 로그에는 최대 20개를 표시합니다.
- 1주 필요 추정 금액은 현재가 × 1.01 + 10원입니다. 실제 주문 직전에 호가·수수료·계좌 현금을 다시 확인합니다. 추천 안내가 설정이나 매수 조건을 자동 변경하지는 않습니다.
- 자료 수집 상태에서 KRX·DART·NAVER의 API 응답 수신과 저장 자료 사용을 구분합니다. 캐시 사용은 현재 입력한 키의 인증 성공을 검증하지 않습니다. READY는 분석 파일 완성을 의미하며 재무·뉴스 통과 개수는 별도로 표시합니다.

- 실행 상태 영역에서 휴장 대기, 매매 시작 대기, 매매시간 종료, 연결 실패를 구분합니다. 휴장 중에는 신규 매수·매도 주문을 보내지 않습니다.
- 다음 개장 시각은 토스 시장 캘린더 응답으로 표시합니다. 응답에 없으면 확인되지 않음으로 표시합니다. 봇은 개장 2분 후부터 마감 동시호가 2분 전까지 매매 조건을 확인합니다.
- 마지막 상태 수신 시각과 경과 초를 표시합니다. 응답이 오래 없으면 응답 지연으로 표시하며 연결 정상으로 판단하지 않습니다.
- 프로그램을 실행해 두면 운영시간과 조건을 계속 확인하지만 개장만으로 매수가 보장되지는 않습니다.

- 실전·읽기 전용 모드, 원금·상한·최근 상태를 표시합니다. 주문 표의 수량은 주문 수량이며 상태와 반영된 체결 수량도 표시합니다.
- 일·주·월·연·전체·직접 기간, 달력과 확대 그래프를 지원합니다. 주는 월요일부터입니다.
- 차트는 봇 관리 자산의 일별 마지막 관측값입니다. 계좌 전체 자산이나 분봉이 아닙니다.
- 카드 수익률은 설정 원금 기준, 그래프는 선택 기간 직전 관측값 기준입니다. 이전 장부에 과거 관측값이 없으면 기록 시작 시의 평가액을 기준으로 합니다. 과거 실적을 만들지 않습니다.
- 최대 낙폭 표시는 기록 기능 추가 이후 관측한 값입니다. 실전과 읽기 전용 기록은 분리됩니다.
- 장외·휴장·시세 오류 시 새 평가값이 없을 수 있으므로 상단 마지막 관측 시각을 확인하세요.

## 중지와 종료

**중지 요청**은 기존 엔진의 미체결 취소·확인을 실행하며 보유분을 매도하지 않습니다. 운용 중 창을 닫으면 중지 후 종료 여부를 묻고 동의 시 봇 종료까지 창을 유지합니다. 통신 장애로 취소가 확인되지 않으면 토스 앱에서 확인해야 합니다.

강제 종료·절전·연결 끊김 시 기존 주문이 남을 수 있습니다. 원금 3만원·1회 9천원·원화 현금 한도와 주문 결과 불명확 시 재전송 금지는 그대로입니다. 실계좌 체결·전략 수익성이 검증되었다는 뜻은 아닙니다.

기존 콘솔은 `python launch_live.py --etf` 또는 `python launch_live.py`로 사용할 수 있습니다.

## 집 인터넷·테더링 전환

IP 변경만으로 토스 API 키를 재발급할 필요는 없습니다. 기존 키를 유지하고 토스증권 웹의 **설정 → Open API → 허용 IP 관리**에서 새 공인 IP를 추가·수정합니다. 등록 가능한 개수 범위에서 집과 테더링 IP를 함께 등록할 수 있습니다. 프로그램은 허용 IP를 자동 등록하지 않습니다.

**중지 요청 → 봇 종료·토스 미체결 확인 → 네트워크 변경 → PC의 공인 IP 확인·등록 → 읽기 전용 점검 → 점검 중지 → 실전 시작** 순서로 진행합니다. 테더링뿐 아니라 집의 유동 IP도 변경될 수 있습니다. 키 자체를 재발급한 경우에만 GUI 인증·계좌 설정의 키를 갱신합니다.

근거: [토스 공식 인증 안내](https://developers.tossinvest.com/docs/auth). Word 매뉴얼의 ‘09 / 접속 환경 변경’에도 같은 절차를 정리했습니다.
# 중지 요청 상태 안내

**최신 계좌·시세 조회**에서 후보가 없거나 조회에 실패하면 `후보 제안 불가 사유` 팝업이 표시됩니다. 시장 운영 상태와 함께 시세 유효시간 초과·예산 부족·추세 미충족·재무/뉴스 미달 등의 실제 제외 종목 수를 안내합니다. 분석 자료 만료·인증/접근 거부·통신 오류·조회 시간 초과는 별도로 안내하며 하단 로그에도 남깁니다. 장 마감 자체를 인증 오류로 판단하지 않습니다.

우측 상단 고정 **프로그램 종료** 버튼 또는 창의 X를 누르면 같은 종료 절차를 수행합니다. 진행 중인 계좌·후보 조회가 끝날 때까지 기다리고, 매매 봇에는 중지를 요청해 미체결 정리·정상 종료를 확인한 뒤 창을 닫습니다. 실패하면 창을 유지하고 안내합니다. 보유분은 매도하지 않으며 종료 후 자동 손절·익절 감시도 끝납니다. 모의매매 결과는 `reports/paper_exit_시각`에 자동 저장하며 저장 실패 시 창을 유지합니다.

중지 요청 접수는 종료 완료가 아닙니다. 진행 중인 작업 응답 후 기존 주문을 조회하고 미체결 정리 결과를 확인합니다. 중지 요청 후 경과 시간이 표시되며, 60초 이상이면 처리 지연 안내가 나옵니다. 통신 지연이나 주문 확인 대기 때문에 더 걸릴 수 있습니다.

정상 종료와 중지 완료 응답을 모두 확인하면 `중지 완료 · 미체결 정리 확인 · 보유 종목 유지 · 자동매매 감시 종료`로 표시합니다. 보유 종목은 강제 매도하지 않으며 중지 후에는 자동 손절·익절 감시도 종료됩니다. `정상 중지 미확인`이면 토스 앱에서 미체결과 보유분을 확인하세요.

# v1.0.25 상태 안내

읽기 전용 점검을 다시 시작하면 하단 우측이 파란색 '새 점검 시작'으로 즉시 바뀝니다.
인증·계좌·시세·호가의 현재 단계가 표시되며, 저장된 분석 자료가 완료 상태여도 새 점검 완료를 의미하지 않습니다.
현재 실행과 자료 수집 결과는 별도 상자에서 확인합니다. 조건 미충족은 노란색, 작업 중단·오류는 빨간색으로 표시합니다.
읽기 전용 점검은 한 번 확인하고 자동 종료하는 기능이 아니라 중지 요청 전까지 주기적으로 다시 확인하는 기능입니다.

# v1.0.26 조회 진행 안내

최신 계좌·시세 조회 버튼은 실행 중인 작업에 먼저 중지를 요청합니다. 정상 중지 확인 후 읽기 전용 조회를 시작하며 보유 종목을 자동 매도하지 않습니다.
진행 팝업은 중지 확인, 조회, 화면 반영 단계와 경과 시간을 보여 줍니다. 확인 버튼 또는 X는 안내창만 닫고 작업은 계속합니다. 결과가 반영되면 안내창은 자동으로 닫힙니다.
중지 확인이 실패하거나 120초를 넘으면 조회를 보류합니다. 조회 자체의 제한 시간은 180초입니다. 조회 후 실전은 자동 재시작하지 않습니다.

# v1.0.28 단일 종목 업종별 추천

1. 단일 종목 프로그램에서 인증·계좌 설정을 엽니다. 토스 계좌와 KRX·DART 인증정보를 저장합니다. 추천 전에는 종목코드를 비워 둘 수 있습니다.
2. 봇을 중지한 상태에서 **업종별 종목 추천 → 예산·재무 기준 조회**를 누릅니다. 기본은 전일 종가로 예산 선별한 종목 중 업종별 시가총액 상위 20개이며 50개 또는 전체로 바꿀 수 있습니다. 이 범위 안에서 최대 5개를 추천하며 전체 시장 최상위 종목이라는 뜻은 아닙니다.
3. 예산은 계좌 원화 주문 가능액, 운용 원금(기존 실전 기록이 있으면 관리 현금), 투자 비중, 주문 상한으로 제한됩니다. 1주 필요액은 조회가 × 1.01 + 10원 추정치입니다. 전일 종가에서 크게 하락해 새로 예산에 들어온 종목은 초기 선별에 포함되지 않을 수 있습니다.
4. 공통 재무 검사 항목은 매출·영업이익·순이익·영업현금흐름 양수 및 자기자본비율 30% 이상입니다. 4개 이상 통과와 영업흑자·순이익 흑자·자본 양수가 필요합니다. 동일 통과 수는 시가총액 순입니다. 금융업은 회계 구조가 달라 공통 지표의 해석에 제한이 있고 표준 항목이 없으면 제외합니다.
5. 한 종목을 클릭하면 재무 수치·연결/별도·보고서 기준일·공시 출처·시세시각을 확인할 수 있습니다. **선택 종목 적용**은 6자리 코드를 설정에 저장할 뿐 매매를 시작하지 않습니다. 읽기 전용 점검 후 실전을 별도로 시작합니다.
6. 장외·휴장 시에는 오래된 시세로 인해 추천이 없을 수 있습니다. 예산 초과, 재무 부족, 시세 미확보 사유는 화면에 표시됩니다. 모든 업종에서 반드시 5개를 채우지는 않습니다. 조회는 최대 30분이며 취소할 수 있습니다.

재무 수집: [OpenDART 단일회사 전체 재무제표 개발가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020). 연결 재무제표를 우선 사용하며 분기 손익은 당기누적금액을 사용합니다. 추천 시점의 가격·회계 검사이며 향후 수익이나 실제 체결을 보장하지 않습니다.

# v1.0.29 설정창과 추천창 연결

단일 종목의 인증·계좌 설정창에서 계좌를 조회·선택하고 KRX·DART 인증정보를 입력한 뒤 **업종별 종목 추천**을 누르세요. 설정창과 추천창을 동시에 사용할 수 있습니다.
추천 조회 후 한 종목을 선택하여 **선택 종목 적용**을 누르면 설정창의 **국내 종목코드 (6자리)**에 자동 입력됩니다. **암호화 저장**으로 확정하세요. 저장 전에는 기존 설정 파일과 매매 상태를 바꾸지 않습니다.
메인 화면에서 직접 여는 추천창은 기존처럼 설정에 바로 적용합니다. 조회 후 인증·계좌 정보가 변경되면 다시 조회해야 합니다.

# v1.0.30 조회 전 준비 안내

예산·재무 기준 조회를 누르면 필수 입력·계좌 선택·예산 설정을 확인합니다. 부족한 항목은 팝업의 안내대로 인증·계좌 설정에서 준비하세요. 종목코드나 ETF 자료를 미리 수집할 필요는 없습니다. 준비가 끝나면 조회를 다시 누르세요. 입력 여부 사전 확인과 실제 API 인증 성공은 구분됩니다.
