파일에서 **`"token": "..."`의 따옴표 안 값**을 복사해서 앱의 토큰 칸에 입력하면 됩니다.

- **서버 주소:** 실제 서버의 `https://도메인또는IP:8443`을 입력합니다. 파일에 `127.0.0.1`이 있으면 휴대폰에서는 실제 서버 주소로 바꿔야 합니다.
- **토큰:** `android-connection.local.json`의 `token` 값입니다. `server.local.json`의 `token_sha256`이나 `client-connection.local.json`의 업로드 토큰과는 다릅니다.

어제 **별도 서버 컴퓨터에서 발급했다면 그 서버에 있는 같은 파일**을 확인해야 합니다. 현재 PC의 토큰과 다를 수 있어요. `--config`로 설정 경로를 지정했다면 해당 설정 파일과 같은 폴더에 생성됩니다.

> 지금 서버 실행했는데 창 상태가 $ !1998
> python3.12 server.py run
> 2026-09-30 13:07:18,749 INFO Listening on ('127.0.0.1', 9443) (TLS=False)
> &#x20;이런데 포트는 9443이고 TLS는 FALSE인데 이상태에서도 토큰이 필요한가?

네, **TLS=False 상태에서도 토큰은 필요합니다.** TLS는 통신 암호화 여부이고, 토큰은 접속 권한 확인용이라 별개입니다.

현재 로그는 **수집기 업로드용 TCP 서버**가 실행됐다는 뜻입니다.

| 구분 | 기본 포트 | 필요한 토큰 |
|---|---|---|
| PC 모니터링 프로그램 → 서버 업로드 | 9443 | `client-connection.local.json`의 `token` |
| Android 앱 → 서버 조회 | 8443 | `android-connection.local.json`의 `token` |

따라서 **Android 앱에 9443을 입력하면 안 됩니다.** 보여주신 로그만으로는 조회용 API도 실행됐는지 확인할 수 없습니다.

또한 `127.0.0.1`은 **서버 컴퓨터 내부에서만 접속 가능한 주소**입니다. 휴대폰에서 접속하려면 서버의 외부 접속 설정과 TLS 인증서 설정이 필요합니다. 현재 코드에서는 외부 접속을 허용할 때 TLS가 필수입니다.

**앞서 보여준 `127.0.0.1:9443 (TLS=False)` 로그만으로는 스마트폰 접속 준비가 된 상태가 아닙니다.** 현재 프로젝트 코드 기준으로 다음을 확인해야 합니다.

1. **앱 주소가 조회 API 주소인지**

   기본 주소 형식은 `https://서버도메인:8443`입니다. `9443`은 수집기 업로드용입니다. 공인 IP로 직접 접속하려면 인증서에도 해당 IP가 포함되어 있어야 합니다.

2. **서버에서 Android API가 실행됐는지**

   시작 로그에 다음과 같은 줄이 있어야 합니다.
   ```text
   Android API listening on ('0.0.0.0', 8443)
   ```
   `127.0.0.1`로 나오면 서버 내부에서만 접속 가능합니다. 이 줄 자체가 없다면 API 활성화 여부부터 확인해야 합니다.

3. **외부 접속 및 TLS 설정이 되어 있는지**

   서버의 `server.local.json`에서 확인하세요.
   - `api.enabled`: `true`
   - `api.host`: 직접 외부 접속을 받을 경우 `"0.0.0.0"`
   - `api.port`: 기본 `8443`
   - `tls.certfile`, `tls.keyfile`: 실제 인증서와 개인키 파일 경로

   **현재 앱은 공인 서버에 HTTP로 접속할 수 없습니다.** 스마트폰이 신뢰하고 접속 주소와 일치하는 HTTPS 인증서가 필요합니다. 설정 변경 후에는 서버를 재시작해야 합니다.

4. **8443 포트가 외부에서 열려 있는지**

   서버 방화벽과 클라우드 보안그룹에서 TCP `8443`을 허용해야 합니다. 공유기 뒤에 있는 서버라면 포트포워딩도 필요합니다. Windows PC에서는 다음으로 연결 여부를 확인할 수 있습니다.
   ```powershell
   Test-NetConnection 실제공인IP -Port 8443
   ```
   `TcpTestSucceeded: True`이면 TCP 연결은 됩니다. 인증서와 토큰 검증은 별도입니다.

5. **실제 서버에서 발급한 조회 토큰인지**

   해당 서버의 `android-connection.local.json` 안에 있는 `token`을 입력해야 합니다.

우선 **공인 서버의 `server.py`가 있는 폴더에서** 아래를 실행해 주세요. 설정을 바꾸지 않고 진단하며 토큰은 출력하지 않습니다.
```bash
python3.12 server.py doctor
```

다음 순서로 진행하세요.

1. **공인 서버에서 조회 API 활성화**

   `server.py`가 있는 폴더에서 실행하세요.
   ```bash
   python3.12 server.py enable-api
   ```
   기본 현장·장비가 아닌 경우 기존 수집기에 등록한 ID를 지정해야 합니다.
   ```bash
   python3.12 server.py enable-api --site 실제현장ID --device 실제장비ID
   ```
   성공하면 같은 설정 폴더의 `android-connection.local.json`에 앱용 토큰이 생성됩니다. **기존 설정이 있어 덮어쓸 수 없다는 오류가 나오면 파일을 삭제하지 말고 오류 내용을 알려주세요.**

2. **HTTPS 인증서와 외부 접속 설정**

   `server.local.json`의 기존 항목을 수정합니다. 아래는 필요한 부분만 보여주는 예시입니다. 기존 `viewers` 등은 유지하세요.
   ```json
   "tls": {
     "certfile": "/실제경로/fullchain.pem",
     "keyfile": "/실제경로/privkey.pem"
   }
   ```
   `api` 안에는 다음 값을 설정하세요.
   ```json
   "enabled": true,
   "host": "0.0.0.0",
   "port": 8443
   ```
   인증서는 스마트폰이 신뢰하고 접속 주소와 일치해야 합니다. **도메인용 인증서라면 앱에서도 해당 도메인으로 접속해야 합니다.**

3. **TCP 8443 허용 후 서버 재시작**

   서버 방화벽·보안그룹에서 TCP `8443`을 허용한 뒤, 기존 서버를 종료하고 실행하세요.
   ```bash
   python3.12 server.py check
   python3.12 server.py run
   ```
   시작 로그에 다음 줄이 나오는지 확인하세요.
   ```text
   Android API listening on ('0.0.0.0', 8443)
   ```

참고로 적어주신 주소의 `61.105d.141.21`에는 **`d` 오타**가 있습니다. 앱에도 들어 있다면 수정하세요. 오류 문구에는 `d`가 없으므로 실제 입력은 정상일 수도 있습니다. 또한 대화에 올린 토큰은 노출된 것으로 보고 교체하는 것이 좋습니다.

**현재 서버에 연결된 도메인과 HTTPS 인증서가 있나요, 아니면 공인 IP만 있는 상태인가요?** 이 부분에 따라 다음 설정 방법이 달라집니다.

> 실제현장ID와 실제장비ID 는 어떻게 정의가 되는거야?

**현장 ID와 장비 ID는 사용자가 정하는 식별 이름입니다.** IP 주소나 자동으로 감지되는 장비 시리얼번호가 아닙니다.

예를 들면:

| 항목 | 의미 | 예시 |
|---|---|---|
| 현장 ID (`site_id`) | 장비가 설치된 장소 | `seoul-ups-room` |
| 장비 ID (`device_id`) | 해당 현장의 개별 장비 | `battery-01` |

**지금은 새로 정하지 말고, 서버에 이미 등록된 값을 확인해서 사용하면 됩니다.**

서버의 `server.local.json`에서 `collectors` → `devices` 부분을 보세요.
```json
"collectors": [
  {
    "id": "collector-01",
    "token_sha256": "...",
    "devices": [
      {
        "site_id": "site-01",
        "device_id": "battery-01"
      }
    ]
  }
]
```

위와 같다면 실행할 명령은:
```bash
python3.12 server.py enable-api --site site-01 --device battery-01
```
`site-01`, `battery-01`은 기본값이므로 이 경우에는 `python3.12 server.py enable-api`만 실행해도 같습니다.

이 두 ID는 **PC 모니터링 프로그램의 ‘서버 TCP 업로드 설정’에도 동일하게 입력**해야 합니다. 수집기가 그 이름으로 데이터를 올리고, 앱의 조회 토큰에는 그 현장·장비를 볼 권한이 부여되는 구조입니다.

네. **현재 구현에는 장비 추가용 API나 전용 명령이 없어서 `server.local.json`을 직접 편집해야 합니다.** 장비 추가 시에는 업로드 권한과 앱 조회 권한을 모두 등록합니다.

현장과 장비는 이렇게 구분하세요.

- **같은 현장에 장비 추가:** `site-01` / `battery-02`
- **새 현장에 장비 추가:** `site-02` / `battery-01`

예를 들어 같은 현장에 `battery-02`를 추가한다면:

1. **`collectors`에서 해당 수집기의 `devices`에 추가** — 데이터를 올릴 권한입니다.
   ```json
   "devices": [
     {"site_id": "site-01", "device_id": "battery-01"},
     {"site_id": "site-01", "device_id": "battery-02"}
   ]
   ```

2. **`api.viewers`에서 조회할 사용자의 `devices`에도 같은 항목 추가** — 앱에서 볼 권한입니다. 기존 조회 토큰은 그대로 사용할 수 있습니다.

3. **새 장비를 수집하는 PC 프로그램에도 동일한 현장 ID·장비 ID를 설정**합니다.

4. 설정을 검사하고 서버를 재시작합니다.
   ```bash
   python3.12 server.py check
   ```
   검사 성공 후 실행 중인 서버를 종료하고:
   ```bash
   python3.12 server.py run
   ```

**새 수집기 PC까지 추가하는 경우에는** `collectors`에 별도의 수집기 ID와 고유 업로드 토큰도 등록하는 방식입니다. `enable-api`는 최초 조회 API 활성화용이므로, 장비가 추가될 때마다 실행하는 명령은 아닙니다.

- **토큰:** `android-connection.local.json`의 `token` 값입니다. `server.local.json`의 `token_sha256`이나 `client-connection.local.json`의 업로드 토큰과는 다릅니다.

어제 **별도 서버 컴퓨터에서 발급했다면 그 서버에 있는 같은 파일**을 확인해야 합니다. 현재 PC의 토큰과 다를 수 있어요. `--config`로 설정 경로를 지정했다면 해당 설정 파일과 같은 폴더에 생성됩니다.

> 지금 서버 실행했는데 창 상태가 $ !1998
> python3.12 server.py run
> 2026-09-30 13:07:18,749 INFO Listening on ('127.0.0.1', 9443) (TLS=False)
> &#x20;이런데 포트는 9443이고 TLS는 FALSE인데 이상태에서도 토큰이 필요한가?

네, **TLS=False 상태에서도 토큰은 필요합니다.** TLS는 통신 암호화 여부이고, 토큰은 접속 권한 확인용이라 별개입니다.

현재 로그는 **수집기 업로드용 TCP 서버**가 실행됐다는 뜻입니다.

| 구분 | 기본 포트 | 필요한 토큰 |
|---|---|---|
| PC 모니터링 프로그램 → 서버 업로드 | 9443 | `client-connection.local.json`의 `token` |
| Android 앱 → 서버 조회 | 8443 | `android-connection.local.json`의 `token` |

따라서 **Android 앱에 9443을 입력하면 안 됩니다.** 보여주신 로그만으로는 조회용 API도 실행됐는지 확인할 수 없습니다.

또한 `127.0.0.1`은 **서버 컴퓨터 내부에서만 접속 가능한 주소**입니다. 휴대폰에서 접속하려면 서버의 외부 접속 설정과 TLS 인증서 설정이 필요합니다. 현재 코드에서는 외부 접속을 허용할 때 TLS가 필수입니다.

`server` 폴더에서 아래 명령을 실행해 주세요. 설정된 인증서 경로와 읽기 가능 여부만 출력하며, 토큰이나 개인키 내용은 출력하지 않습니다.

```bash
python3.12 - <<'PY'
import json
from pathlib import Path

config = Path("server.local.json").resolve()
print("설정 파일:", config)
try:
    data = json.loads(config.read_text(encoding="utf-8-sig"))
except Exception as e:
    print("설정 읽기 실패:", e)
    raise SystemExit(1)

for key in ("certfile", "keyfile"):
    value = data.get("tls", {}).get(key)
    if not value:
        print(key, ": 경로가 설정되지 않았습니다.")
        continue
    path = Path(value)
    if not path.is_absolute():
        path = config.parent / path
    print(key, ":", path)
    try:
        with path.open("rb") as f:
            f.read(1)
        print("  읽기 성공")
    except OSError as e:
        print("  읽기 실패:", e)
PY
```

   from datetime import datetime
   from pathlib import Path

- `0.0.0.0:8443`: 스마트폰 조회용, HTTPS로 외부 접속 가능하도록 대기 중
