위 도메인과 ID는 설명용입니다. 실제 주소와 ID로 바꿔 사용하세요. 방 접속 ID는 개인 아이디나 서버 관리자 비밀번호가 아닙니다. 서버 주소만으로는 기존 방에 입장할 수 없습니다.

현재 개발 PC의 주소는 http://localhost:8000입니다. localhost는 접속하는 사람 자신의 PC를 뜻합니다. 다른 PC의 사람에게 localhost 주소를 공유하면 그 사람이 이 서버에 접속하는 것이 아닙니다. 여러 PC를 연결하려면 서버 관리자가 제공한 HTTPS 주소를 사용하세요.

방장은 방을 운영하는 역할이고, 발표자는 현재 말하거나 화면을 공유하는 역할입니다. 일반 참여자도 방장이 발표자로 지정하면 발표할 수 있습니다. 발표자로 지정하는 것과 방장 권한을 넘기는 것은 다른 동작입니다.

기본값과 현재 제공 범위

  • 입장 설정에서 마이크·스피커는 기본 꺼짐이며 카메라도 기본 꺼짐입니다. 직전 회의에서 사용했어도 새 입장 시 다시 확인합니다.
  • 서버 주소와 표시 이름만 같은 브라우저에 저장할 수 있습니다. 장치 사용 여부와 참가 인증 토큰은 영구 저장하지 않습니다.
  • 기본 한 방 최대 인원은 8명입니다. 관리자가 설정을 바꿀 수 있으나, 실제 수용 인원은 서버와 네트워크 성능을 검증해 정해야 합니다.
  • 자동 회의록은 한국어 음성 인식 결과를 발언자별로 묶고 결정·실행 후보를 추출합니다. 생성형 AI 요약이나 사실 확인 기능은 포함하지 않습니다.
  • 파일은 발표자가 열어 둔 창을 공유하는 방식입니다. 파일 업로드, 공동 문서 편집, 시스템 소리 공유는 제공하지 않습니다.
  • 영상·음성 녹화 파일은 저장하지 않습니다. 회의록 텍스트는 서버 DB에 저장합니다.
  • 진행 중인 방, 발표권, 화이트보드는 서버 메모리에 있습니다. 서버가 재시작되면 이전 방은 복원되지 않습니다. 회의록 DB는 별도로 보존됩니다.
  • 대기실, 참가 승인, 강제 퇴장, 전체 참가자 강제 종료, 수동 방장 양도, 사용자 계정 인증은 현재 화면에 없습니다.

빠른 시작

일반 참여자는 초대 링크 열기 → 이름 확인(서버 주소·방 접속 ID 자동 입력) → 회의 참여하기 → 스피커 켜기 → 필요시 손들기와 마이크 켜기 순서로 사용합니다. 서버 주소와 접속 ID를 직접 입력하는 방법도 가능합니다.

방장은 주소 열기 → 새 회의 만들기 → 방식과 회의록 옵션 선택 → 새 회의 시작하기 → 참석자 탭에서 초대 링크 복사 → 발표 지정 → 회의록 저장 순서로 진행합니다.

서버 관리자는 설치 환경 확인 → 서버 파일 배치 → Python 3.12와 systemd 준비 → 도메인·네트워크 설정 → 서비스 실행 → 다중 PC 시험 → 자동 시작 확인 순서로 구축합니다.

방장이 공유한 초대 링크 또는 서버 주소와 방 접속 ID로 입장하는 사람을 위한 안내입니다. 별도의 Python 설치는 필요하지 않습니다.

초대 링크로 빠르게 참여하기

  1. 방장이 보낸 초대 링크를 Chrome 또는 Edge에서 엽니다. 예: https://meet.example.com/#room=4AB891762964.
  2. 초대 링크로 접속했습니다 안내와 자동 입력된 서버 주소·방 접속 ID를 확인합니다. 이전에 저장한 서버 주소가 있어도 초대 링크의 서버를 사용합니다.
  3. 내 이름을 입력하거나 저장된 이름을 확인합니다.
  4. 마이크·스피커·카메라를 사용할지 선택합니다. 기본값은 모두 꺼짐이며 링크를 여는 것만으로 입장하거나 장치를 켜지 않습니다.
  5. 회의 참여하기를 누릅니다. 입장 후 상대방 소리를 들으려면 스피커를 켜세요.

링크의 ID가 올바르지 않다는 안내가 나오면 방장에게 전체 링크를 다시 받으세요. 종료된 방은 기존 링크로 들어갈 수 없으므로 새 방의 링크를 받아야 합니다. 링크 없이 서버 주소와 접속 ID를 받은 경우에는 아래 절차를 따릅니다.

1 접속 전에 준비하기

  1. 방장에게 중계 서버 주소와 방 접속 ID를 받습니다.
  2. PC에서 Chrome 또는 Edge를 엽니다. 화면 공유는 데스크톱 브라우저를 기준으로 설명합니다.
  3. 헤드셋 또는 이어폰을 연결합니다. 마이크가 있는지 확인합니다.
  4. 다른 화상회의 앱이 카메라·마이크를 사용 중이면 정리합니다.
  5. 주소창에 방장이 알려준 주소를 입력합니다. 예: https://meet.example.com.

브라우저의 장치 권한과 프로그램의 장치 버튼은 별개입니다. 브라우저에서 마이크 사용을 허용했더라도 프로그램의 마이크가 꺼져 있으면 음성이 전달되지 않습니다.

3 방에 들어가기

  1. 회의 참여 탭을 선택합니다.
  2. 내 이름을 입력합니다.
  3. 방 접속 ID를 입력합니다.
  4. 입장할 때 사용할 마이크·스피커·카메라를 선택합니다. 모두 꺼 둔 상태로도 입장할 수 있습니다.
  5. 회의 참여하기를 누릅니다.
  6. 카메라나 마이크 권한 창이 나오면 사용하려는 장치에 대해 허용합니다.
  7. 방 이름과 참석자 목록에 본인 이름이 표시되는지 확인합니다.
  8. 상대방 말을 들으려면 하단 스피커 꺼짐을 눌러 스피커 켜짐으로 바꿉니다.

입장 직후 자신의 이름만 보인다면 다른 참석자가 아직 들어오지 않았을 수 있습니다. 참석자는 보이지만 영상·음성이 계속 연결되지 않으면 관리자에게 네트워크 점검을 요청하세요.

4.2 FREE Talk에서 말하기

  1. 스피커를 켭니다.
  2. 마이크를 켭니다.
  3. 다른 참석자들과 자유롭게 이야기합니다.
  4. 여러 사람이 동시에 말할 수 있으므로 필요하지 않을 때는 마이크를 끕니다.

FREE Talk에서는 발언을 위해 발표권을 받을 필요가 없습니다. 다만 화면 공유와 화이트보드 그리기는 여전히 발표자 권한이 필요합니다.

4.3 회의 모드에서 말하기

  1. 하단의 손들기를 누릅니다.
  2. 버튼이 손 내리기로 바뀌고, 방장의 참석자 목록에 발언 요청이 표시됩니다.
  3. 방장이 본인을 발표 지정할 때까지 기다립니다.
  4. 본인이 발표자라는 안내를 확인합니다.
  5. 마이크가 꺼져 있으면 직접 켭니다. 발표권을 받아도 마이크가 자동으로 켜지지는 않습니다.
  6. 발표권이 다른 사람에게 넘어가면 본인의 음성이 서버에서 차단되고, 켜 둔 마이크는 대기 상태가 됩니다.

발표권은 한 명에게만 지정됩니다. 자동 회의록 옵션이 꺼져 있어도 회의 모드는 한 사람씩 발표합니다. 자동 순번 배정 기능은 없고 방장이 발표 순서를 정합니다.

발표자현재 발표자의 카메라 또는 공유 화면을 크게 표시발표·문서 설명 보기

화면 배치는 본인의 화면에만 적용됩니다. 내가 화이트보드로 바꿨다고 다른 사람도 자동으로 바뀌지 않습니다. 발표자가 화면을 공유하면 각자 발표자 탭을 선택해 크게 보세요. 전체 화면은 Esc로 나올 수 있습니다.

카메라가 꺼진 참석자는 영상 대신 이름의 첫 글자가 표시됩니다. 화면을 어떤 탭으로 바꾸더라도 스피커를 켜 두었다면 참석자의 음성은 계속 들립니다.

6 발표자로 지정됐을 때 화면과 파일 공유하기

6.1 열린 파일 함께 보기

  1. 발표할 PDF, 문서, 스프레드시트, 슬라이드 또는 이미지를 PC에서 먼저 엽니다.
  2. 방장에게 발표자로 지정해 달라고 요청합니다.
  3. 하단 화면·파일 공유를 누릅니다.
  4. 브라우저 선택 창에서 공유할 창, 탭 또는 전체 화면을 선택합니다.
  5. 공유를 시작하고 참석자에게 발표자 탭을 선택해 달라고 안내합니다.
  6. 파일을 넘기거나 스크롤하면서 설명합니다.
  7. 설명이 끝나면 공유 중지 또는 브라우저의 공유 중지 버튼을 누릅니다.

공유 중에는 본인의 카메라 영상 자리에 공유 화면이 전송됩니다. 카메라와 화면을 동시에 두 개의 영상으로 전송하지 않습니다. 공유를 멈추면 켜 둔 카메라로 돌아가고, 카메라가 꺼져 있으면 아바타로 돌아갑니다.

이 기능은 파일을 서버에 업로드하지 않습니다. 다른 참석자가 파일을 다운로드하거나 함께 수정하는 기능은 없습니다. 동영상이나 음악의 시스템 소리는 공유하지 않으며 발표자의 마이크로 설명합니다. 공유할 창에 표시되는 내용은 참석자가 볼 수 있으니 공유 대상을 선택할 때 확인하세요.

6.2 화이트보드 사용하기

  1. 화이트보드 탭을 선택합니다.
  2. 본인이 현재 발표자인지 확인합니다.
  3. 펜 색과 두께를 선택합니다.
  4. 마우스를 누른 채 움직이거나 터치로 그립니다.
  5. 참석자는 자신의 화이트보드 탭에서 내용을 봅니다.

지우기는 보드 전체를 지웁니다. 실행 취소나 부분 지우개는 없습니다. 지운 내용은 되돌릴 수 없으므로 함께 보고 있는 사람이 내용을 확인했는지 먼저 확인하세요. 화이트보드 저장·내보내기 버튼도 없으므로 필요한 그림은 회의 중 OS 화면 캡처로 보관합니다.

늦게 입장한 사람도 현재 방의 그림을 받습니다. 그러나 마지막 사람이 나가거나 서버가 재시작되면 보드는 사라집니다.

7 회의록 보기와 저장하기

  1. 오른쪽 회의록 탭을 누릅니다.
  2. 음성 인식 기록 중 또는 자동 기록 꺼짐 표시를 확인합니다.
  3. 자동 기록 중이면 발표자의 발언이 문장 단위로 잠시 뒤 표시됩니다.
  4. 방장이 추가한 확정 결정, 실행 항목, 추가 메모를 확인합니다.
  5. 상단 회의록 저장을 누릅니다.
  6. 브라우저 다운로드 폴더에서 회의록-접속ID.md 파일을 확인합니다.

일반 참여자도 자기 방의 회의록을 다운로드할 수 있습니다. 일반 참여자는 기록을 추가·수정하거나 자동 기록 옵션을 바꿀 수 없습니다. 전사 오류가 있으면 방장에게 정정 메모를 남겨 달라고 요청하세요.

화면에는 최근 200개 기록이 표시되며 다운로드 파일에는 그 시점까지 DB에 저장된 전체 기록이 들어갑니다. 마지막 발언은 인식 완료까지 시간이 걸릴 수 있으므로 발언을 마친 뒤 기록이 표시됐는지 확인하고 저장하세요. 저장 파일의 시간은 UTC이며 한국 시간은 UTC보다 9시간 빠릅니다. 화면의 시간은 브라우저 현지 시간으로 표시됩니다.

8 나가기와 다시 입장하기

  1. 필요한 회의록을 먼저 저장합니다.
  2. 하단 나가기를 누릅니다.
  3. 접속 설정 화면으로 돌아왔는지 확인합니다.

같은 방에 다른 사람이 남아 있다면 동일한 접속 ID로 다시 들어갈 수 있습니다. 새로고침이나 브라우저 종료도 연결을 끊을 수 있으며, 자동 재입장 기능은 없습니다. 재입장 시 마이크·스피커·카메라는 다시 확인하세요.

마지막 사람이 나가면 방이 종료됩니다. 종료된 접속 ID는 다시 사용할 수 없으며 방장이 새 방을 만들어야 합니다. 혼자 있는 방에서 새로고침해도 기존 방이 종료될 수 있습니다.

방을 만든 사람이 처음 방장이 됩니다. 방장은 회의 방식과 자동 기록 여부를 정하고 발표 순서를 관리합니다. 본인의 장치 조작은 일반 참여자 사용법과 같습니다.

1 방을 만들기 전에 정하기

선택FREE Talk회의 모드

방의 방식은 생성할 때 선택합니다. 진행 중인 방을 FREE Talk에서 회의 모드로 바꾸는 버튼은 없습니다. 변경하려면 기록을 저장하고 새 방을 만든 뒤 새 접속 ID를 공유하세요.

2 새 방 만들기

  1. 서버 관리자가 알려준 HTTPS 주소를 Chrome 또는 Edge에서 엽니다.
  2. 중계 서버 주소를 확인하고 연결 확인을 누릅니다.
  3. 내 이름을 입력합니다. 예: 김민수 팀장.
  4. 마이크·스피커·카메라 사용 여부를 정합니다. 기본값은 모두 꺼짐입니다.
  5. 새 회의 만들기 탭을 선택합니다.
  6. 회의 이름을 입력합니다. 예: 제품팀 주간 회의. 최대 80자입니다.
  7. 회의 방식에서 FREE Talk 또는 회의 모드를 선택합니다.
  8. 자동 기록이 필요하면 회의 모드에서 음성 인식으로 자동 회의록 작성을 선택합니다.
  9. 새 회의 시작하기를 누릅니다.
  10. 회의 화면에서 본인의 방장 표시, 회의 이름, 접속 ID를 확인합니다.

방을 만들면 방장 자신이 최초 발표자로 지정됩니다. 마이크가 꺼져 있다면 발표자여도 음성이 나오지 않으므로 직접 켜야 합니다.

자동 회의록 옵션이 비활성화되어 있으면 FREE Talk가 선택됐는지, 서버 연결 확인이 성공했는지, 안내에 한국어 모델 미설치 또는 로딩 실패가 표시되는지 확인하세요. 모델 설치 문제는 서버 관리자가 해결해야 합니다.

3 초대 링크·접속 ID 공유와 참석자 확인

  1. 방을 만든 뒤 오른쪽 참석자 탭에서 참여자 초대 링크를 확인합니다. 방장에게 표시되는 메뉴입니다.
  2. 초대 링크 복사를 누르고 이메일·메신저 등 원하는 수단에 붙여 넣습니다.
  3. 참석자에게 링크를 열고 이름과 장치 설정을 확인한 뒤 회의 참여하기를 누르도록 안내합니다. 서버 주소와 방 접속 ID는 자동 입력됩니다.
  4. 오른쪽 참석자 탭에서 이름과 인원수를 확인합니다.

공유 예:

text
회의: 제품팀 주간 회의
초대 링크: https://meet.example.com/#room=4AB891762964

링크를 열고 이름을 입력한 뒤 회의 참여하기를 눌러 주세요.
마이크와 스피커는 기본 꺼짐입니다.
입장 후 스피커를 켜고, 발언할 때는 손들기를 눌러 주세요.

방 접속 ID는 서버가 자동으로 생성합니다. 방장이 직접 지정하거나 기존 방의 ID를 바꾸는 기능은 없습니다. 코드 자체가 입장 수단이므로 참석할 사람에게 공유하세요. 현재는 방장 승인 대기실이나 별도 입장 비밀번호가 없습니다.

클립보드 복사가 실패하면 링크 입력란이 선택됩니다. Ctrl+C 또는 모바일의 길게 누르기로 직접 복사하세요. 기존 상단 접속 ID 복사로 서버 주소와 접속 ID를 전달하는 방법도 사용할 수 있습니다.

초대 링크에는 방 접속 ID만 포함되고 방장 인증 토큰은 포함되지 않습니다. 링크를 받은 사람은 일반 참여자로 입장합니다. 다른 사람에게 전달된 링크로도 입장할 수 있으므로 참석할 사람에게 공유하세요. 방장이 먼저 나가면 다음 방장에게 초대 메뉴가 표시됩니다.

마지막 참석자가 나가거나 서버가 재시작되어 방이 종료되면 기존 링크로 재입장할 수 없습니다. 새 방을 만들고 새 링크를 공유하세요. localhost 주소는 다른 PC용 초대 주소로 사용할 수 없습니다. 외부 초대는 참석자가 접속할 수 있는 HTTPS 서버 주소로 접속해 방을 만든 뒤 링크를 복사합니다.

4 회의 시작 점검

  1. 전원에게 스피커를 켜 달라고 안내합니다.
  2. 본인이 발표자인지 확인하고 마이크를 켭니다.
  3. 짧게 말한 뒤 참석자가 듣는지 확인합니다.
  4. 참석자 한 명을 발표자로 지정해 반대 방향 음성도 확인합니다.
  5. 화면 공유와 화이트보드를 쓸 예정이면 각 기능을 한 번 확인합니다.
  6. 자동 회의록을 사용하는 회의임을 참석자에게 알리고 기록 상태를 확인합니다.

서버 주소가 열리고 방에 입장할 수 있다는 것만으로 영상·음성이 연결된 것은 아닙니다. 다른 네트워크의 참석자가 있다면 그 참석자의 영상·음성도 확인하세요.

5 발표 순서 운영하기

5.1 일반 참여자에게 발표권 주기

  1. 오른쪽 참석자 탭을 엽니다.
  2. 발언을 요청한 사람의 이름 옆에 발언 요청 표시가 있는지 확인합니다.
  3. 해당 사람의 발표 지정 버튼을 누릅니다.
  4. 해당 사람이 발표자로 표시되는지 확인합니다.
  5. 그 사람의 마이크가 꺼져 있다면 직접 켜 달라고 안내합니다.

발표자로 지정된 사람의 손들기 표시는 해제됩니다. 이전 발표자의 음성은 회의 모드에서 차단됩니다. 이전 발표자가 화면을 공유 중이었다면 공유도 중지되므로 발표권을 넘기기 전에 설명이 끝났는지 확인하세요.

5.2 방장 자신이 다시 발표하기

  1. 참석자 목록에서 본인 이름을 찾습니다.
  2. 본인 옆 발표 지정을 누릅니다.
  3. 본인의 마이크를 켜거나 켜진 상태인지 확인합니다.

방장이란 이유만으로 다른 발표자와 동시에 말할 수 있는 것은 아닙니다. 회의 모드에서는 방장에게도 동일한 단일 발표 규칙이 적용됩니다.

5.3 FREE Talk 진행하기

FREE Talk에서는 모두 마이크를 켜면 동시에 말할 수 있습니다. 이때 발표자 지정은 주로 공유 화면과 화이트보드 조작자를 정하기 위해 사용합니다. 방장이 다른 사람의 마이크를 강제로 켜거나 끄는 기능은 없습니다.

6 자동 회의록 운영하기

6.1 진행 중 켜기와 끄기

  1. 오른쪽 회의록 탭을 선택합니다.
  2. 회의 모드에서 켜기를 누릅니다.
  3. 음성 인식 기록 중 표시를 확인합니다.
  4. 현재 발표자가 마이크를 켜고 말합니다.
  5. 발언자 이름과 전사 내용이 표시되는지 확인합니다.
  6. 기록을 중지할 때 끄기를 누릅니다.

옵션을 켠 뒤의 음성만 인식합니다. 꺼져 있던 구간을 나중에 복구해 기록하지 않습니다. 옵션을 끄거나 발표권이 바뀌는 순간 직전 발언의 마지막 인식 결과가 잠시 뒤 도착할 수 있습니다. 자동 기록을 끄더라도 이미 저장된 기록은 지워지지 않습니다.

6.2 정확도를 높이는 진행 방법

  • 한 번에 한 사람이 말하고, 말이 끝날 때 짧게 쉬어 줍니다.
  • 마이크를 입 가까이에 두고 불필요한 주변 소음을 줄입니다.
  • 사람 이름, 제품명, 숫자, 날짜, 약어는 전사 결과를 확인합니다.
  • 중요한 결정은 방장이 다시 확인하고 별도의 확정 기록으로 남깁니다.

화면의 자동 전사는 검토할 원문입니다. 현재 버전은 전사를 문맥에 따라 완전히 교정하거나 고급 요약하는 기능이 아닙니다.

6.3 확정 결정과 실행 항목 남기기

  1. 회의록 탭의 방장 기록 추가로 이동합니다.
  2. 종류를 선택합니다.
  3. 내용을 작성하고 기록 추가를 누릅니다. 한 번에 최대 2,000자입니다.
종류기록 예
추가 메모전사 정정: 제품 이름은 모아입니다.
확정 결정시제품 검토 회의는 10월 21일 수요일 14시에 진행한다.
실행 항목담당: 홍길동 / 작업: 시제품 화면 초안 공유 / 기한: 10월 20일 18시

기존 기록의 편집·삭제 버튼은 없습니다. 잘못 입력했으면 추가 메모로 정정 내용을 남기세요. 자동 추출된 결정·실행 후보를 확인했더라도 확정 내용으로 남기려면 방장이 해당 종류로 새로 기록해야 합니다.

6.4 회의록 저장 파일의 구성

회의록 저장을 누르면 다음 순서로 정리된 Markdown 파일을 내려받습니다.

  1. 회의 제목, 시작·내보내기 시각
  2. 기록에 등장한 발언자
  3. 발언자별 주요 논의 원문
  4. 방장이 입력한 확정 결정
  5. 방장이 입력한 실행 항목
  6. 추가 메모
  7. 키워드로 자동 분류한 결정·실행 후보
  8. 시간순 원문

참석 발언자는 전체 출석부가 아닙니다. 기록에 등장한 사람을 기준으로 하므로 조용히 듣기만 한 사람은 빠질 수 있습니다. 부정문도 키워드 후보로 잡힐 수 있어 자동 후보는 미확정 상태로 분리됩니다.

7 발표 자료와 화이트보드 진행

방장도 현재 발표자여야 화면·파일 공유와 화이트보드 그리기를 사용할 수 있습니다. 파일을 먼저 연 뒤 공유할 창을 선택하고 참석자에게 발표자 화면으로 바꿔 달라고 안내하세요.

화이트보드를 쓸 때는 참석자에게 각자 화이트보드 탭을 선택하도록 안내합니다. 지우기는 전체 내용을 삭제하며 되돌리기 기능은 없습니다. 기록이 필요한 그림은 회의가 끝나기 전에 화면 캡처로 보관하세요.

8 회의 종료와 방장 퇴장

정상 종료 순서

  1. 마지막 발표자의 발언을 마칩니다.
  2. 마지막 전사 내용이 표시되는지 확인합니다.
  3. 확정 결정과 실행 항목의 담당자·기한을 확인합니다.
  4. 회의록 저장으로 최종 파일을 내려받습니다.
  5. 필요한 참석자도 회의록을 저장하도록 안내합니다.
  6. 참석자들에게 나가 달라고 안내합니다.
  7. 방장은 마지막으로 나가기를 누릅니다.

방장이 나가기만 해서는 전체 회의가 끝나지 않습니다. 다른 참석자가 남아 있으면 그중 한 사람에게 방장 권한이 자동으로 이전됩니다. 현재는 전체 방 종료 버튼이 없습니다.

방장이 먼저 나가거나 연결이 끊긴 경우

  • 서버는 남아 있는 접속자 중 먼저 들어온 사람을 우선하여 방장으로 정합니다.
  • 원하는 사람을 직접 방장으로 지정하는 UI는 없습니다. 발표자 지정은 방장 이전 기능이 아닙니다.
  • 기존 방장이 다시 입장해도 이전 권한이 자동 복구되지 않습니다.
  • 모든 사람이 나가면 방은 종료되고 기존 접속 ID로 다시 들어갈 수 없습니다.
  • 새로고침도 연결 종료로 처리될 수 있으므로 진행 중인 방장 화면을 불필요하게 새로고침하지 마세요.

1. 다운로드 및 최초 설치

bash
sudo apt update
sudo apt install -y git ca-certificates
git clone https://github.com/forlovesea/work.git
cd work/WebConference/RelayServer
sudo bash deploy/native/build-python.sh
sudo bash deploy/native/install.sh

빌드는 기본 2개 작업으로 실행합니다. 메모리가 부족하면 sudo env JOBS=1 bash deploy/native/build-python.sh를 사용하세요. 기존 별도 Python 3.12가 있다면 빌드를 생략하고 sudo bash deploy/native/install.sh /절대경로/python3.12로 설치할 수 있습니다. 서비스는 홈 디렉터리에 접근하지 못하므로 Python을 /home 아래에 설치하지 마세요.

설치기는 전용 moa 계정, 릴리스별 가상환경, 한국어 모델, 설정 파일, systemd 서비스를 구성합니다. 설정은 최초 한 번만 생성하며 업데이트 때 보존합니다. 서버는 127.0.0.1:8000에서만 HTTP 요청을 받습니다. 설치 직후 외부 HTTPS는 아직 구성되지 않은 상태입니다.

2. HTTPS 설정

DNS가 실제 서버를 가리키고 TCP 80/443이 도달 가능해야 합니다. 기존 프록시가 있다면 포트를 중복 점유하지 않도록 기존 설정에 사이트를 추가하세요.

bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo cp deploy/native/nginx.conf /etc/nginx/sites-available/moa
sudo nano /etc/nginx/sites-available/moa
# server_name을 실제 도메인으로 변경
sudo ln -s /etc/nginx/sites-available/moa /etc/nginx/sites-enabled/moa
sudo nginx -t
sudo systemctl enable --now nginx
sudo systemctl reload nginx
# 아래 도메인도 실제 값으로 변경
sudo certbot --nginx -d meet.example.com --redirect
sudo systemctl enable --now certbot.timer
sudo certbot renew --dry-run

https://실제도메인으로 접속하세요. Nginx는 WebSocket Upgrade 전달과 긴 연결을 지원하도록 구성했습니다. 공식 설명. 폐쇄망은 조직 CA 인증서를 Nginx에 설정하고 클라이언트가 해당 CA를 신뢰하도록 구성하세요. 다른 PC의 카메라·마이크·화면 공유에는 신뢰되는 HTTPS가 필요합니다.

3. 미디어 및 TURN

WebRTC 미디어는 HTTPS와 별도 UDP 연결입니다. cat /proc/sys/net/ipv4/ip_local_port_range로 서버 범위를 확인하고 방화벽·보안그룹·NAT에 반영하세요. NAT 환경은 TURN을 구성하고 서로 다른 외부 네트워크에서 시험해야 합니다. HTTP 8000은 외부에 열지 않습니다.

bash
sudo apt install -y coturn
# 기존 coturn 운영 중이면 덮어쓰지 말고 기존 설정에 통합
sudo cp deploy/turnserver.conf /etc/turnserver.conf
sudo nano /etc/turnserver.conf

realm, user=meeting:강한임의비밀번호, 필요 시 external-ip=공인IP/사설IP를 설정합니다. TCP/UDP 3478과 UDP 49160–49260을 허용합니다. /etc/default/coturn을 사용하는 패키지는 TURNSERVER_ENABLED=1도 설정합니다.

bash
sudo systemctl enable --now coturn
sudo systemctl restart coturn
sudo journalctl -u coturn -n 50 --no-pager
sudo nano /etc/moa/moa.env

systemd 환경 파일에서는 JSON 전체를 작은따옴표로 감쌉니다.

text
ICE_SERVERS_JSON='[{"urls":"turn:meet.example.com:3478?transport=udp","username":"meeting","credential":"실제비밀번호"}]'

sudo systemctl restart moa로 적용합니다. 재시작은 진행 중인 회의를 종료합니다. worker 수를 늘리면 방과 WebRTC 상태를 공유하지 못하므로 단일 프로세스를 유지하세요.

4. 업데이트와 롤백

회의를 종료하고 백업한 뒤 Git 체크아웃의 RelayServer에서:

bash
git pull --ff-only
sudo bash deploy/native/install.sh

새 릴리스에서 의존성과 모델을 확인한 뒤 current 링크를 전환하고 서비스를 재시작합니다. 기존 가상환경·DB·설정은 덮어쓰지 않습니다. 이전 릴리스 경로를 출력하며 자동 삭제하지 않습니다. 시작 후 상태 검사가 실패하면 종료 코드 1로 중단합니다. 필요하면 수동 롤백하세요.

bash
sudo systemctl stop moa
# 실제 이전 릴리스 경로로 변경
sudo ln -sfn /opt/moa/releases/release-PREVIOUS /opt/moa/current
sudo systemctl start moa

롤백은 코드·가상환경만 바꾸며 DB 및 설정은 되돌리지 않습니다. 향후 DB 형식 변경은 해당 버전 복원 지침도 확인해야 합니다. Python 보안 패치는 별도 설치 후 새 인터프리터를 install.sh 인자로 전달하여 가상환경을 다시 만드세요.

5. 자동 시작, 로그, 백업

bash
sudo systemctl is-enabled moa
sudo systemctl restart moa
sudo systemctl stop moa              # 이번 실행만 중지
sudo systemctl disable --now moa     # 부팅 자동 시작 해제
sudo systemctl enable --now moa      # 재개
sudo journalctl -u moa -f

설치기가 부팅 자동 시작을 등록합니다. 재부팅 후 서비스가 살아나도 진행 중이던 방은 복구되지 않으므로 새 방을 만드세요.

회의 종료 후 서비스를 멈추고 DB와 WAL/SHM을 포함한 상태 디렉터리 및 설정을 함께 백업합니다. 백업에는 회의록과 TURN 암호가 포함됩니다.

bash
sudo systemctl stop moa
sudo install -d -m 0700 /var/backups/moa
sudo sh -c 'umask 077; tar -czf /var/backups/moa/backup-$(date +%Y%m%d-%H%M%S).tar.gz /var/lib/moa /etc/moa'
sudo systemctl start moa

복원은 서비스를 멈춘 상태에서 수행하고 /var/lib/moa 소유자를 moa:moa로 유지하세요. Windows/Docker DB 이전도 양쪽 서비스를 중지하고 남아 있는 WAL/SHM까지 함께 옮깁니다. 새 DB와 기존 DB를 각각 백업한 뒤 이전하세요.

6 검증 범위

Windows에서 앱 회귀 테스트와 설치 셸 구문 검사를 수행합니다. Ubuntu의 apt 설치·소스 컴파일·systemd/Nginx/coturn 실행과 외부망 연결은 대상 서버에서 최종 검증해야 합니다. 기존 Docker 파일은 이전 배포 호환용이며 이 절차에서는 사용하지 않습니다.

1 Ubuntu 자동 시작

서버 설치 안내의 직접 설치 스크립트가 moa.service를 등록합니다. Docker는 필요하지 않습니다.

sudo systemctl enable --now moa
sudo journalctl -u moa -b --no-pager

재부팅 후에도 상태와 /api/health, /api/config를 확인하세요. 서버 재시작 시 진행 중인 방은 종료되며, 기존 회의록 DB는 보존됩니다.

2 중지와 재개

bash
sudo systemctl stop moa
sudo systemctl restart moa
sudo systemctl disable --now moa
sudo systemctl enable --now moa

stop은 이번 실행만 중지하며 다음 부팅에는 다시 시작합니다. 자동 시작까지 해제하려면 disable --now를 사용하세요.

5 Windows 부팅 자동 시작

Windows는 개발·시험용으로 설명합니다. 다른 PC 사용자를 받는 운영 서버는 HTTPS와 네트워크 구성이 추가로 필요합니다.

5.1 등록할 실행 파일과 경로 확인

현재 PC에서:

항목값
작업 이름 예MoaMeetingRelay
프로그램C:\Users\063\Downloads\교육_1014\화상회의\.venv\Scripts\python.exe
인수"C:\Users\063\Downloads\교육_1014\화상회의\RelayServer\server.py" --host 127.0.0.1 --port 8000
시작 위치C:\Users\063\Downloads\교육_1014\화상회의\중계서버

새 PC에서 RelayServer/.venv를 만들었다면 프로그램 경로도 그 위치로 변경합니다. 가상환경이 참조하는 원본 Python도 작업 실행 계정이 읽고 실행할 수 있어야 합니다. Python, 프로젝트 폴더, 모델을 나중에 이동하면 작업 설정도 다시 맞춰야 합니다.

5.2 작업 스케줄러에서 등록

  1. 시작 메뉴에서 작업 스케줄러를 검색해 엽니다. 부팅 작업 등록에는 관리자 권한이 필요할 수 있습니다.
  2. 오른쪽에서 작업 만들기를 선택합니다.
  3. 일반 탭에서 이름을 MoaMeetingRelay로 입력합니다.
  4. 실행 계정은 프로젝트·Python·모델을 읽고 data 폴더에 쓸 수 있는 계정으로 선택합니다.
  5. 사용자의 로그온 여부에 관계없이 실행을 선택합니다. 서버 실행 자체에 관리자 권한이 꼭 필요한 것은 아니므로 불필요하게 SYSTEM이나 최고 권한을 사용하지 않습니다.
  6. 트리거 탭에서 새로 만들기 → 작업 시작: 시작할 때/시스템 시작 시를 선택합니다. 네트워크 준비를 위해 30초 정도 지연을 설정할 수 있습니다.
  7. 동작 탭에서 프로그램 시작을 선택하고 위 표의 프로그램·인수·시작 위치를 각각 입력합니다. 전체 명령을 프로그램 칸 하나에 넣지 않습니다.
  8. 조건 탭에서 서버용 전원 정책에 맞춰 유휴·전원 조건을 확인합니다. 노트북을 실제로 배터리에서도 운영할 경우에만 AC 전원 조건을 조정합니다.
  9. 설정 탭에서 요청 시 작업 실행 허용을 켭니다.
  10. 실패 시 다시 시작은 예를 들어 1분 간격·3회로 설정합니다.
  11. 작업이 다음 시간 이상 실행되면 중지 같은 장시간 실행 제한을 해제합니다. 서버는 계속 실행되는 프로그램입니다.
  12. 이미 실행 중일 때는 새 인스턴스 시작 안 함을 선택해 중복 서버를 막습니다.
  13. 저장하고 요청되는 실행 계정 인증을 완료합니다. 인증 정보는 작업 스케줄러에 입력하며 문서나 명령 파일에 비밀번호를 적지 않습니다.

부팅 트리거는 시스템 시작 시 작업을 실행하도록 구성하는 방식입니다. 계정과 권한 조건도 충족되어야 합니다. Microsoft 부팅 트리거 예제.

5.3 수동 시험 후 재부팅 시험

  1. 콘솔에서 수동 실행한 서버가 있으면 먼저 그 콘솔에서 Ctrl+C로 종료합니다.
  2. 작업 스케줄러에서 MoaMeetingRelay를 선택하고 실행을 누릅니다.
  3. 상태가 실행 중인지 확인합니다. 계속 실행되는 서버에서는 작업 완료가 아니라 실행 중 상태가 정상입니다.
  4. 브라우저에서 http://localhost:8000을 엽니다.
  5. 필요하면 PowerShell에서 다음을 확인합니다.
powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
Invoke-RestMethod http://127.0.0.1:8000/api/config
Get-ScheduledTask -TaskName MoaMeetingRelay
Get-ScheduledTaskInfo -TaskName MoaMeetingRelay
  1. 회의가 없는 시간에 PC를 재부팅합니다.
  2. 별도 수동 실행 없이 작업이 시작되는지 확인합니다. 로그인 전 시험이 필요하다면 적절한 HTTPS·방화벽 구성을 갖춘 다른 PC에서 확인합니다. 기본 127.0.0.1 바인딩은 다른 PC에서 접근할 수 없습니다.
  3. 모델 준비와 실제 새 방 생성도 확인합니다.

화면에 콘솔이 없다고 실행되지 않은 것은 아닙니다. 비대화형 작업은 창을 표시하지 않을 수 있습니다. 반대로 부팅에 성공했어도 Windows가 절전 상태로 들어가면 네트워크 서비스가 계속 제공되지 않으므로 서버 운영에 맞는 절전 설정을 적용합니다.

5.4 작업 중지와 해제

작업 스케줄러에서 해당 작업의 끝내기로 현재 서버를 중지하고, 사용 안 함으로 다음 부팅 실행을 막습니다. 삭제는 등록 자체를 제거합니다. 완료 후 포트와 health 응답을 확인하세요. 실행 계정 비밀번호나 폴더 경로가 바뀌면 작업 설정도 갱신해야 합니다.

5.5 시작프로그램 폴더를 사용하는 간단한 대안

로그인할 때만 실행돼도 되는 개발 PC라면 Win+R에 shell:startup을 입력하고 RelayServer/run.cmd의 바로가기를 넣을 수 있습니다. Python 실행 파일 자체를 복사하지 않습니다. 해제하려면 이 바로가기를 제거합니다.

이 방식은 로그인 전에는 시작하지 않고 실패 시 자동 복구도 제공하지 않습니다. 작업 스케줄러와 동시에 등록하면 포트 중복이 생길 수 있으므로 둘 중 하나만 사용합니다.
