# RemoteControl v0.4.5 프로그램 사용 매뉴얼

## 1. 역할과 시작 전 확인

Host는 조작하는 폰, Target은 화면을 보여주고 제어받는 폰/태블릿입니다. 두 기기는 같은 Wi-Fi일 필요가 없으며 각각 인터넷으로 중계서버에 연결합니다. 중계서버는 켜져 있어야 하고 두 앱에는 같은 서버 주소·접속 키가 설정되어 있어야 합니다.

이 버전은 사용자가 직접 화면 공유를 승인하는 방식입니다. 무인 부팅 후 자동 공유, 잠금 해제, 오프라인 기기 깨우기는 제공하지 않습니다.

## 2. Target 준비

1. 앱을 열고 서버 주소, 서버 접속 키, 기기 이름을 확인합니다.
2. ‘서버 연결 / 자동 재접속 시작’을 누릅니다. 연결 상태와 지속 알림을 확인합니다.
3. 보기만 허용하려면 ‘이번 세션에서 터치 제어 허용’을 끕니다.
4. 터치 제어도 허용하려면 ‘터치 제어 권한 설정’에서 접근성 서비스를 켜고 ‘이번 세션에서 터치 제어 허용’을 선택합니다.
5. ‘화면 공유 시작’을 누르고 앱 안내와 Android 시스템 공유 창을 승인합니다.
6. 공유 중에는 Target에서 여는 화면이 Host에 보일 수 있습니다. 필요할 때만 공유하세요.

기기 이름/서버 주소/키를 바꾸려면 ‘공유 / 연결 즉시 중지’로 연결을 종료한 뒤 변경합니다. 공유 중 제어 허용 여부를 바꾸려면 공유를 중지하고 새 설정으로 다시 시작하세요.

## 3. Host 연결과 조작

1. 앱에 서버 주소와 접속 키를 입력합니다.
2. ‘서버 연결 / 목록 새로고침’을 누릅니다. 앱이 전면에 있는 동안 목록은 약 5초마다 갱신됩니다.
3. ‘연결 가능’인 Target을 선택합니다. 연결되면 전체화면으로 전환됩니다.
4. 화면을 탭하거나 끌어서 터치/스와이프를 전달합니다. Target에서 제어를 허용하고 접근성 서비스가 준비된 경우에만 동작합니다.
5. ‘뒤로’, ‘홈’ 버튼으로 해당 동작을 실행합니다.
6. ‘화면 보기’에서 화면에 맞춤, 전체화면, 작게 보기 중 선택합니다. 작게 보기에서도 좌표는 Target 화면에 맞게 변환합니다.
7. ‘연결 종료’를 누르면 원격 연결을 종료합니다. Target의 공유 권한이 유지되면 다시 목록에서 선택할 수 있습니다.

Host 앱을 다른 앱으로 전환하면 연결이 종료됩니다. 다시 Host로 돌아온 후 Target을 선택하세요. 한 Target에 동시에 여러 Host가 연결할 수 없습니다. 서버의 기본 원격 세션 제한은 30분이며 종료 후 다시 연결해야 합니다.

## 4. Target 화면 켜짐 유지

Host의 **‘연결 중 Target 화면 켜짐 유지’**를 켭니다. 기본값은 꺼짐이며 선택값은 저장됩니다. 전체화면에서도 옵션을 바꿀 수 있습니다.

- 이미 화면이 켜진 Target과 공유 연결이 성립한 동안, 상태 확인 신호에 유지 명령을 함께 보냅니다.
- 보기 전용 연결에서도 사용할 수 있습니다. 터치 접근성 권한은 이 옵션에 필요하지 않습니다.
- 옵션 해제는 다음 상태 확인 신호에 반영됩니다. 연결 종료/공유 중지 시 유지가 해제됩니다.
- 네트워크 장애로 명령이 끊기면 마지막 유지 신호로부터 최대 15초 후 유지가 만료됩니다. 이후 실제 화면 꺼짐 시점은 기기 설정을 따릅니다.
- Target이 목록에서 사라진 상태나 공유 연결 전에는 작동하지 않습니다.
- 전원 버튼으로 직접 잠그는 동작, OS의 공유 권한 회수, 앱 강제 종료를 막지 않습니다.
- 화면과 통신이 유지되는 동안 배터리 소모가 늘어납니다. 장시간 사용 시 전원 상태를 확인하세요.

v0.4.4의 ‘화면 깨우기’ 버튼은 제거되었습니다. 양쪽 앱을 v0.4.5로 맞춰 설치하세요. 구버전 Target은 새 유지 명령을 지원하지 않습니다.

## 5. 목록과 연결 상태 읽기

| 표시 | 의미 / 조치 |
| --- | --- |
| 화면 공유 승인 필요 | 서버에는 접속했으나 공유 준비가 안 됨. Target에서 화면 공유 시작/승인 |
| 연결 가능 | 선택하여 연결 가능 |
| 사용 중 | 다른 Host가 연결 중이거나 세션 정리 중. 기존 연결 종료 후 갱신 |
| 목록에서 사라짐 | Target의 서버 연결이 종료되었거나 시간 초과. Target 인터넷/앱 상태 확인 |
| 화면 보기 전용 | 화면 확인 가능, 터치 허용 안 됨 |
| Target 터치 제어 권한 확인 필요 | 접근성 서비스 또는 세션 허용 상태 확인 |

Host의 하단 상태줄은 응답 시간과 변동, 지연 응답 비율을 보여줍니다. 주의 단계는 1~10으로 높을수록 나쁜 상태입니다. 초록은 원활, 노랑은 지연, 주황은 느림, 빨강은 심한 지연/무응답을 뜻합니다. 파랑은 보기 전용, 회색은 대기 상태입니다. 상태줄을 누르면 설명이 표시됩니다. 전체화면에서는 하단 표시가 숨겨지므로 화면 보기에서 다른 모드로 전환하여 확인하세요.

약 5초 무응답이면 제어를 차단하고 약 10초 무응답이면 연결을 종료합니다. 표시되는 지연 응답 비율은 TCP 패킷 손실률이 아니며, 초록 상태도 개별 터치 성공까지 보장하지 않습니다.

## 6. 중지와 종료

Target의 ‘공유 / 연결 즉시 중지’는 화면 공유와 서버 연결을 모두 중지합니다. ‘프로그램 종료’는 앱을 종료하고 터치 접근성 서비스도 비활성화하므로 다음 사용 때 다시 켜야 할 수 있습니다. 알림의 중지/연결 종료 버튼으로도 종료할 수 있습니다.

Host의 ‘연결 종료’는 현재 원격 연결을 끝냅니다. 전체화면에서 ‘화면 보기’를 바꾸면 설정 영역을 다시 볼 수 있습니다. ‘프로그램 종료’는 Host 앱을 종료합니다.

## 7. 키 파일과 진단 로그

‘표시’는 접속 키를 잠시 확인하는 옵션입니다. ‘키 위치’는 서버 접속 키 파일 위치를 안내합니다. ‘키 파일 저장’으로 기기 공유 저장소의 원하는 위치에 키를 저장하고, ‘키 파일 불러오기’로 다시 입력할 수 있습니다. 파일 선택 후 서버 연결 시 앱 설정에도 저장됩니다.

키 파일은 비밀 정보입니다. 새 서버로 바꿨다면 그 서버에 맞는 키를 사용하세요. ‘키파일 삭제’는 선택한 파일과 이 앱에 저장된 키를 지웁니다. 서버 자체의 키를 바꾸는 기능은 아닙니다.

문제가 생기면 양쪽 앱에서 ‘진단 로그 공유’를 눌러 파일로 저장하거나 지원 담당자에게 전달하세요. 비밀 키/화면 데이터는 로그에 기록하지 않도록 구현되어 있으나 공유 전 내용은 확인하세요. 앱 삭제/데이터 삭제 시 내부 로그도 삭제됩니다.

## 8. 자주 발생하는 문제

| 증상 | 확인할 내용 |
| --- | --- |
| 서버에 접속 실패 | 새 서버 주소인지, 포트 55000~60000인지, DNS/인터넷/방화벽 및 서버 서비스 상태 |
| TLS 인증 실패 | 인증서 도메인/체인/만료, 기기 날짜/시간. 인증서 검증을 끄지 말고 서버 설정 수정 |
| 서버 접속 키 오류 | 서버의 access.key와 양쪽 앱의 64자리 키 일치 여부 |
| Target이 목록에 없음 | Target 서버 연결 시작, 같은 서버/키, 네트워크 및 절전 상태 |
| 연결 가능이 안 뜸 | Target 화면 공유 승인 여부. 공유를 중지 후 다시 시작 |
| 화면은 보이나 터치 불가 | Target 세션 터치 허용, 접근성 서비스, Host 응답 상태 |
| 잠금/회전 후 공유 종료 | Target 잠금 해제 후 다시 공유 승인. 회전 시 새 세션 필요 |
| 화면 유지 옵션인데 꺼짐 | 두 앱 버전, 실제 공유 연결, 네트워크 단절, 전원 버튼/OS 정책 확인. Target 로그 수집 |
| Host 화면 검게 표시 | DRM/보안 화면 여부, 공유 상태, 화면 프레임 오류 로그 확인 |
| 재부팅 후 연결 안 됨 | Target 앱을 열어 서버 연결 및 공유 승인을 다시 수행 |

## 9. 제공하지 않는 기능

자동 잠금 해제, 공유 승인 우회, 오프라인 깨우기, Host 자동 재연결, 음성 전송, 파일 전송, 클립보드, 멀티터치는 구현되어 있지 않습니다. 현재 버전의 실기기 검증은 설치 후 각 기기에서 수행해야 합니다.
