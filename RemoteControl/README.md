# RemoteControl Android

Android 기기 간 원격 화면 공유·제어를 위한 **공인 서버 중계 MVP**입니다. Java 17 / Android SDK 35 / Gradle 8.11.1 기반이며 Android 8.0(API 26) 이상을 대상으로 합니다.

```text
Host 스마트폰 (LTE / Wi-Fi)
            ↕ 외부 연결 · TLS
Ubuntu 20.04 중계서버 (공인 IP, TCP 55000 기본)
            ↕ 외부 연결 · TLS
Target 스마트폰 (LTE / Wi-Fi)
```

두 스마트폰 모두 중계서버에 연결하므로 같은 Wi-Fi나 스마트폰 포트 포워딩이 필요하지 않습니다. 서버 배포 절차는 [server/README.md](server/README.md)에 있습니다. 서버 접근 정보가 제공되지 않아 실제 공인 서버 배포는 아직 수행하지 않았습니다.

## 역할과 설치

| 선택 | 앱 ID | 기능 |
| --- | --- | --- |
| Host | `com.remotecontrol.host` | Target 화면 수신, 탭·스와이프·뒤로·홈 명령 전송 |
| Target | `com.remotecontrol.target` | 사용자 승인으로 화면 송출, 선택적으로 터치 제어 허용 |

Android 기본 APK 설치 화면에는 사용자 정의 역할 선택 항목을 넣을 수 없습니다. 따라서 **하나의 프로젝트에서 두 APK를 빌드**하고 설치할 APK를 선택합니다. Host에는 Target의 서비스와 접근성 권한이 포함되지 않습니다. 동일 기기에 두 앱을 각각 설치할 수도 있습니다.

- 휴대폰 직접 설치: `dist/RemoteControl-host-debug.apk` 또는 `dist/RemoteControl-target-debug.apk`를 선택합니다.
- USB 설치: PowerShell에서 `./install.ps1`을 실행하면 역할을 선택할 수 있습니다. USB 디버깅을 켜고 PC 연결을 승인해야 합니다.
- 지정 설치: `./install.ps1 -Role host -Serial DEVICE_SERIAL` 또는 `-Role target`.
- 제공 APK는 **개발용 Debug 서명**입니다. 정식 배포 서명/스토어 배포는 별도 작업입니다.

## 사용 순서 (v0.4.0)

**중계서버·Host·Target을 모두 업데이트해야 합니다.** 기존 서버에는 자동 기기 목록 기능이 없습니다. 서버 업데이트는 [server/README.md](server/README.md)를 참고하세요.

1. 서버에서 `access.key`를 생성하고 새 서버를 시작합니다. 이 서버 접속 키는 서버 관리자와 허용한 Host·Target만 공유합니다.
2. Target에 서버 주소(예: `61.105.141.21:55000`), 서버 접속 키, 목록에 표시할 기기 이름을 입력하고 **서버 연결 / 자동 재접속 시작**을 누릅니다.
3. Host에 동일한 서버 주소와 서버 접속 키를 입력하고 **서버 연결 / 목록 새로고침**을 누릅니다. 접속한 Target 목록이 5초마다 갱신됩니다. 기기별 접속 정보 붙여넣기는 필요하지 않습니다.
4. Target에서 **화면 공유 시작**을 누르고 Android 화면 공유를 승인합니다. 터치 제어를 원하면 접근성 서비스를 켜고 **이번 세션에서 터치 제어 허용**을 선택합니다.
5. Host 목록에서 **연결 가능**인 Target을 누릅니다. 연결 후 전체화면으로 전환됩니다. **화면 보기**에서 화면에 맞춤·전체화면 보기·작게 보기(맞춤 크기의 55%)를 선택할 수 있습니다. 작은 화면도 터치 좌표를 실제 Target 화면에 맞춰 변환합니다. 전체화면에서도 보기 옵션과 연결 종료 버튼이 남습니다.
6. Target의 **공유 / 연결 즉시 중지** 또는 **프로그램 종료**로 중지합니다. Host와 Target 모두 **프로그램 종료** 버튼으로 앱을 닫을 수 있습니다. Target에서 프로그램 종료는 접근성 서비스도 비활성화하므로 다음 제어 사용 시 다시 켜야 합니다.

Host와 Target의 서버 접속 키 입력란은 **표시**로 평문 전환이 가능하고, **키 위치**에서 서버 기본 키 파일(`/etc/remotecontrol/access.key`)과 `sudo cat /etc/remotecontrol/access.key` 확인 명령을 볼 수 있습니다. 서비스에 `--access-key-file`을 지정했다면 그 경로를 확인하세요. **키 파일 저장**으로 키를 공용 Documents/Downloads 등 앱 삭제 후에도 남는 위치에 저장하고, 재설치 후 **키 파일 불러오기**로 선택하면 다시 입력할 필요가 없습니다. 앱 삭제 후 파일을 다시 고르는 것은 Android 저장소 권한 정책상 필요합니다. **키파일 삭제**는 선택한 공유 파일과 앱 내부에 암호화 저장된 키를 삭제합니다. 공유 키 파일은 비밀 정보이므로 안전한 위치에 보관하고, 불필요해지면 삭제하세요. 공유 화면에 나오는 일회용 Target 세션 키가 아니라 서버 접속 키를 양쪽에 입력해야 합니다.

## 문제 분석용 진단 로그

Host와 Target 앱은 연결 단계, TLS/세션 인증 성공·실패, 첫 화면 프레임, 캡처·전송 예외를 앱 내부에 기록합니다. 비밀번호·서버 접속 키·일회용 세션 토큰·화면 이미지/제어 데이터는 기록하지 않으며, 로그는 앱 전용 저장소에 최대 약 512KB(최근 2개 파일)만 유지합니다.

문제가 재현되면 **Host에서 Target 연결을 한 번 시도한 다음**, 두 기기에서 각각 화면 오른쪽 위의 **진단 로그 공유**를 눌러 로그를 저장하거나 전달해 주세요. 양쪽 로그에 같은 시각의 실패 단계가 있어야 TLS 종료 지점을 비교할 수 있습니다. 공유 전에 주소나 기기 이름처럼 개인 정보가 없는지도 확인하세요. 앱 데이터를 지우거나 앱을 삭제하면 기기 내부 로그도 삭제됩니다.

### Target 인증 실패

연결 단계별 실패 원인과 다음 조치를 Host에 표시합니다. **Target 인증서 불일치**이면 Target에서 화면 공유를 중지하고 다시 시작한 뒤 Host 목록을 새로고침하세요. **Target이 TLS 연결을 먼저 닫았습니다**라고 표시되면 Target 앱 화면에 나온 TLS 핸드셰이크 오류도 확인하세요. **화면 프레임 생성 실패 (연결 유지)**는 프레임 하나만 버리고 다음 프레임을 계속 전송합니다. 반복되면 Target 기기의 지원 화면 크기/메모리를 확인하세요. **화면 전송 연결 종료**는 Target 앱에서 네트워크/화면 전송 상태를 확인하고 공유를 다시 시작하세요. **Target 세션 인증 실패**는 새 공유 세션을 시작하고 Host 목록을 새로고침하세요. **중계서버 TLS 연결 실패**이면 Target 인증 문제가 아니므로 서버 주소와 서버 TLS 인증서를 확인하세요. Host와 Target은 같은 최신 앱 버전을 사용해야 합니다.

Samsung Android 15에서 `RSA routines: ... internal error`와 함께 TLS 핸드셰이크가 닫히는 문제를 진단 로그에서 확인한 경우, Host와 Target 앱을 모두 새 버전으로 업데이트하세요. 새 Target은 Android Keystore에서 P-256 ECDSA 인증서를 사용하고 TLS 1.2 ECDHE-ECDSA 암호 방식만 협상해 오류를 일으키던 RSA 서명 경로를 사용하지 않습니다. 새 인증서 지문은 공유 시작 시 서버에 자동 등록됩니다. 서비스/소켓 종료는 메인 스레드의 네트워크 작업을 피하도록 변경했습니다. 중계서버 업데이트는 필요하지 않습니다.

## 목록 상태와 자동 재접속

- **화면 공유 승인 필요**: Target은 서버에 접속했지만 공유 세션이 아직 준비되지 않았습니다.
- **연결 가능**: Target에서 화면 공유를 승인했고 Host를 기다리는 중입니다.
- **사용 중**: 한 Host가 연결한 상태입니다. 다른 Host는 동시에 접속할 수 없습니다.
- Target 연결이 종료되거나 연결 확인 응답이 30초 동안 없으면 목록에서 제외됩니다. 네트워크 복구 후 자동 재등록합니다. 인터넷 상태에 따라 목록 반영은 지연될 수 있습니다.

Target의 서버 연결 유지 알림은 화면 공유와 별개입니다. 서버 연결 확인은 10초마다 수행하며 오류 후 3초 대기 뒤 재접속합니다(연결 시도 시간 제한 별도). 화면 공유의 대기 소켓은 최대 60초마다 교체하므로 짧게 대기 상태로 표시될 수 있습니다. Host 연결이 끊긴 뒤에도 Target은 공유 권한이 유지되는 동안 다시 연결 대기로 돌아갑니다. Host에서 목록의 기기를 다시 선택하면 됩니다.

화면 잠금 시 앱이 직접 Target을 서버에서 연결 해제하지 않으며, 중계서버 연결 유지는 화면 공유와 독립된 포그라운드 서비스가 담당합니다. Android/제조사가 잠금 화면에서 MediaProjection 권한을 회수하면 화면 공유 세션만 종료될 수 있습니다. 잠금 화면은 Android 보안 정책상 송출할 수 없으며, 잠금 해제 후 Target에서 화면 공유를 다시 승인해 시작하세요. 화면 회전·시스템 공유 종료 후에도 새 공유 승인이 필요합니다. 앱 강제 종료, OS의 프로세스 종료 또는 재부팅 후 자동 시작은 지원하지 않습니다. 서버의 개별 원격 연결은 최대 30분이며 이후 Target은 다시 대기합니다.

서버 접속 키는 최초 설정 후 Android Keystore 키로 암호화해 저장합니다. 서버 접속 키를 아는 Host는 해당 서버의 모든 Target 목록을 보고 공유 승인된 Target에 연결할 수 있습니다. 개별 사용자·기기별 권한 분리는 지원하지 않습니다. 접속 키는 공개하지 마세요.

## Host 하단 실시간 상태 표시

원격 화면 아래 고정 표시줄에 색상과 설명을 함께 표시합니다.

v0.3.0부터 연결 품질을 **10단계의 색 종류와 진하기**로 표시합니다. 같은 색 계열에서 진할수록 상태가 나쁩니다. 표시줄을 누르면 색상 설명을 볼 수 있습니다.

| 주의 단계 | 색상 | 기본 응답 시간 기준 / 의미 |
| --- | --- | --- |
| 1 | 옅은 초록 | 100ms 미만 · 매우 원활 |
| 2 | 초록 | 100~199ms · 원활 |
| 3 | 옅은 노랑 | 200~349ms · 약간의 지연 |
| 4 | 노랑 | 350~499ms · 지연이 느껴짐 |
| 5 | 옅은 주황 | 500~699ms · 반응이 느림 |
| 6 | 주황 | 700~999ms · 느림, 끊김 주의 |
| 7 | 진한 주황 | 1,000~1,499ms · 매우 느림 |
| 8 | 옅은 빨강 | 1,500ms 이상 · 심한 지연, 끊김 의심 |
| 9 | 빨강 | 5초 이상 응답 없음 · 제어 입력 차단 |
| 10 | 진한 빨강 | 8초 이상 응답 없음 / 연결 끊김 |

최근 응답 시간뿐 아니라 진행 중인 응답 대기 시간, 최근 10회 응답의 변동과 지연 응답 비율을 함께 평가하여 더 나쁜 단계를 선택합니다. 변동은 인접 응답 시간 차이의 평균이며 3회 이상 수집하면 75/150/300/500ms에서 최소 3/5/7/8단계로 올립니다. 700ms 이상인 응답의 비율은 4회 이상 수집하면 10/30/50%에서 최소 4/6/7단계로 올립니다. 마지막 응답 후 2.5/3.5초 경과 시에도 최소 6/8단계가 됩니다. 최근 측정이 안정되면 오래된 나쁜 표본이 10회 창에서 빠지면서 회복합니다.

상태줄에는 최근 응답 시간, 변동(ms), 지연 응답 비율, 표본 수와 길어진 응답 대기 시간을 함께 표시합니다. 지연 응답 비율은 **패킷 손실률이 아니며**, TCP 재전송 횟수나 개별 제어 명령 성공률을 측정하는 기능은 아닙니다. 정지 화면의 낮은 프레임 수를 끊김으로 오인하지 않습니다. v0.2.0과 통신 형식은 동일합니다.

| 색상 | 의미 |
| --- | --- |
| 초록 | Target 응답 양호, 첫 화면 수신 완료, 터치 제어 권한 준비됨 |
| 노랑 | 연결/응답/첫 화면 확인 중 또는 Target 제어 권한 확인 필요 (연결 품질은 위 10단계 적용) |
| 빨강 | Target 응답 없음 또는 연결 끊김 |
| 파랑 | 응답 양호, 화면 보기 전용 세션 |
| 회색 | 연결 전 또는 사용자가 종료한 상태 |

1초 간격으로 Target까지 왕복 상태 확인을 시도하고, 표시줄은 0.5초 간격 및 응답 수신 시 갱신합니다. 응답 시간(ms)은 중계 경로와 Target 메인 스레드 확인 시간을 포함합니다. 5초 이상 응답이 없으면 빨강이며 제어 입력을 막습니다. 10초 동안 응답이 없으면 연결을 종료합니다. 지연 상태에서 응답이 회복되면 상태도 자동으로 회복됩니다.

화면 변화가 없는 정지 화면은 연결 장애로 판단하지 않습니다. 초록색은 최근 통신 응답과 제어 준비 상태를 나타내며, 개별 터치가 대상 앱에서 실제로 수행됐는지까지 보장하는 표시는 아닙니다. 접근성 서비스를 끄면 다음 상태 응답에 반영됩니다.

## 빌드와 검사

Android Studio에서 이 폴더를 열고 JDK 17 및 Android SDK 35를 설정합니다. Build Variant에서 `hostDebug` 또는 `targetDebug`를 선택합니다.

```powershell
./build-debug.ps1
# 이미 의존성이 캐시된 이 작업 환경에서는:
./build-debug.ps1 -Offline
# PowerShell 실행 정책으로 차단될 경우 이 프로세스에서만 실행:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./build-debug.ps1 -Offline
```

스크립트는 `JAVA_HOME`, `ANDROID_HOME`, `GRADLE_USER_HOME`을 우선 사용합니다. 미설정 시 이 작업 폴더의 기존 `../BatteryWatch/android-app/` 개발 도구와 Gradle 캐시를 재사용합니다. 다른 PC에서는 JDK/SDK를 설치하고 환경 변수를 설정하세요. 애플리케이션 소스와 런타임은 BatteryWatch에 의존하지 않습니다.

```text
./gradlew :app:assembleHostDebug :app:assembleTargetDebug
./gradlew :app:testHostDebugUnitTest :app:testTargetDebugUnitTest
./gradlew :app:lintHostDebug :app:lintTargetDebug
```

`build-debug.ps1`은 빌드·단위 테스트·Lint를 모두 통과한 후 두 APK와 SHA-256 체크섬을 `dist/`에 복사합니다.

## 구조와 통신

- `app/src/main`: 화면 구성 공통 코드, 서버 목록 프로토콜, 암호화된 설정 저장, TLS 인증서 고정 검증.
- `app/src/host`: TLS 클라이언트, JPEG 화면 표시, 화면 여백을 제외한 터치 좌표 변환.
- `app/src/target`: Android Keystore 인증서, MediaProjection 포그라운드 서비스, 세션 중에만 동작하는 AccessibilityService.
- `app/src/test`: 접속 정보 검증 및 잘못된 제어 좌표 거부 테스트.
- `server`: Python 3.8 이상 표준 라이브러리 기반 TLS 중계서버, 자동 테스트, systemd 서비스.
- `docs/DEVICE_TESTS.md`: 실제 기기 검증 절차.

두 앱은 서버 인증서와 호스트명을 검증한 TLS 연결로 서버에 접속합니다. 서버 접속 키로 인증한 Target이 기기 ID와 이름을 등록하고 연결 확인 응답을 유지합니다. 화면 공유를 승인하면 Target이 인증서 지문과 일회용 세션 키를 서버에 등록합니다. Host는 기기 ID로 연결을 요청하고 서버가 제공하는 세션 정보를 사용해 내부 TLS를 연결합니다. Target 내부 TLS 서버는 루프백에만 바인딩합니다.

화면/제어 데이터는 별도의 TLS 1.2 터널로 전달합니다. Target 개인키는 Android Keystore에 보관합니다. **서버가 기기 목록, 인증서 지문, 세션 키를 관리하므로 서버와 서버 관리자를 신뢰하는 구조입니다.** 서버가 악의적인 경우까지 보호하는 외부 지문 검증 모델은 아닙니다. 목록과 세션 키는 서버 메모리에만 보관하고 로그에 기록하지 않습니다.

인증 이후 Target→Host는 `int32 JPEG 길이 + JPEG bytes` 프레임을 전송합니다. 상태 응답은 길이 위치에 `int32 -1`을 쓰고 `int64 ping 식별자 + boolean 세션 제어 허용 + boolean 제어 준비`를 덧붙입니다. 화면/상태 패킷은 같은 출력 잠금으로 직렬화하여 섞이지 않게 합니다. Host→Target은 `uint8 명령`을 전송하며, 제스처 명령에는 정규화한 좌표 4개(`float32`)와 시간(`int32 ms`)이 추가됩니다. 상태 확인 명령은 `uint8 4 + int64 Host 단조 시각`이며, Target은 이 값을 그대로 응답합니다. Java DataInput/OutputStream의 big-endian 형식입니다. 화면은 긴 변 최대 960px, 최대 약 5fps의 JPEG이며 오디오는 없습니다.

## 현재 범위와 제한

- 실제 기기에서의 연결·화면 공유·제어 검증은 `docs/DEVICE_TESTS.md`의 미완료 항목입니다. 빌드 성공이 기기 동작을 보장하지는 않습니다.
- 계정별 권한, Host 자동 재연결, 무인 화면 공유, 파일 전송, 키보드 입력, 멀티터치, 오디오는 구현하지 않았습니다. 서버의 자동 기기 목록과 Target 자동 재접속은 지원합니다.
- LTE↔Wi-Fi 전환으로 기존 TCP 연결이 끊기면 Target이 자동 재접속합니다. Host는 상태 응답이 10초 동안 없으면 연결을 종료하며 목록에서 기기를 다시 선택해 연결해야 합니다.
- 화면 회전 시 세션을 종료하여 이전 좌표가 잘못된 위치를 누르는 것을 방지합니다. 회전 후 다시 공유하세요.
- 보안 화면/DRM 콘텐츠는 Android에 의해 검게 표시될 수 있습니다. 잠금 해제나 시스템 권한 승인 우회는 지원하지 않습니다.
- Android 및 제조사에 따라 외부 APK의 접근성 설정에 추가 사용자 승인이 필요할 수 있습니다.
- 초기 중계 프로토타입입니다. 고성능 제품화에는 비디오 인코딩/WebRTC, 대역폭 제어 및 다양한 기기 검증이 필요합니다. 공통 서버 접속 키 인증을 사용하며, 다중 사용자 운영에는 계정별 권한과 트래픽 정책을 추가해야 합니다.

## 연결 중 Target 화면 켜짐 유지 (v0.4.5)

Host의 **연결 중 Target 화면 켜짐 유지** 옵션을 켜면 인증된 화면 공유 연결에서 주기적으로 유지 신호를 보냅니다. 기본값은 꺼짐이며 선택값을 저장합니다. 전체화면에서도 옵션을 변경할 수 있고, 보기 전용 연결에서도 사용할 수 있습니다. 화면 깨우기 버튼은 제거했습니다.

Host와 Target을 모두 v0.4.5 이상으로 업데이트한 후 사용하세요. 이 기능은 기존 중계서버의 화면 공유 터널을 사용하므로 서버 추가 업데이트가 필요하지 않습니다. 구버전 Target에 옵션을 켜면 새 명령을 지원하지 않아 연결이 종료될 수 있습니다.

Target은 화면이 켜져 있을 때만 유지하며, 잠든 기기를 깨우거나 잠금을 해제하지 않습니다. 옵션 해제는 다음 상태 확인 신호에 반영되고, 연결 종료/공유 중지 시 즉시 해제됩니다. 연결 장애로 신호가 끊기면 마지막 유지 신호로부터 최대 15초 뒤 유지가 만료됩니다. 이후 화면 꺼짐은 기기의 설정을 따릅니다. Host 앱이 백그라운드로 가면 기존 정책대로 연결이 종료됩니다. 전원 버튼으로 직접 잠그거나 OS가 공유를 중단하는 것을 막지 않습니다. 화면 유지 중에는 배터리 소모가 늘어납니다.
