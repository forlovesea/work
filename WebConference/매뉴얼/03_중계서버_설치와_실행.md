# 중계서버 설치와 실행

서버 관리자를 위한 설치·네트워크·운영 안내입니다. Ubuntu 20.04 호스트에서 Docker로 실행하는 구성을 기본으로 하며, Windows 개발 PC의 직접 실행 방법도 설명합니다. 실제 Ubuntu 서버의 도메인·공인 IP·방화벽 값은 해당 환경에 맞게 바꿉니다.

## 1 구성과 설치 조건

```text
참여자 브라우저
  ├─ HTTPS 및 WebSocket → Caddy → Python FastAPI 서버
  └─ WebRTC 영상·음성 → Python aiortc 중계
                              └─ NAT 환경에서는 coturn 경유 가능

Python 서버
  ├─ 방·참가자·발표권 관리
  ├─ 화이트보드 동기화
  ├─ 한국어 Vosk 음성 인식
  └─ SQLite 회의록 저장
```

Python 서버와 네트워크 통신 모두 중계 서버를 사용합니다. 파일 공유는 브라우저 화면 공유로 처리합니다. 서버는 브라우저 화면까지 제공하므로 별도 웹 서버 프로그램을 직접 작성할 필요는 없습니다.

### 1.1 Ubuntu 20.04의 지원 상태

Ubuntu 20.04의 일반 보안 지원은 2025년 5월 29일 종료됐습니다. 유지 운영 시 Ubuntu Pro/ESM 적용 범위를 확인하세요. 2026년 10월 기준 최신 Docker 설치 문서의 지원 대상은 Ubuntu 22.04·24.04·26.04이며, 20.04는 포함되지 않습니다. [Ubuntu 지원 공지](https://lists.ubuntu.com/archives/ubuntu-security-announce/2025-May/009421.html), [Docker Ubuntu 요구사항](https://docs.docker.com/engine/install/ubuntu/).

아래 20.04 절차는 **기존 서버를 유지해야 하는 환경에서 남아 있는 focal 패키지를 사용하는 설치 경로**입니다. 현재 [Docker focal 패키지 저장소](https://download.docker.com/linux/ubuntu/dists/focal/pool/stable/amd64/)는 확인되지만, 저장소가 남아 있다는 사실이 최신 버전 지원이나 보안 유지보수를 보장하지는 않습니다. 이미 관리 중인 Docker가 정상 설치돼 있으면 재설치하지 말고 버전과 Compose 동작을 확인한 뒤 3장부터 진행하세요.

애플리케이션 컨테이너는 `python:3.12-slim-bookworm`을 사용합니다. Ubuntu 20.04 기본 Python 3.8에 서버 패키지를 직접 설치하는 방식은 이 안내의 기본 경로가 아닙니다. Windows에서 기능 테스트를 완료한 구성으로, 실제 Ubuntu·방화벽·NAT 조합은 아래 설치 후 시험으로 확인해야 합니다.

### 1.2 준비 목록

| 항목 | 준비 내용 |
| --- | --- |
| 서버 | Ubuntu 20.04 64비트, sudo 권한. 아래 설치 예는 amd64 기준 |
| 성능 | 소규모 시험 출발점으로 4 vCPU·8GB RAM·20GB 여유 공간을 잡고 실제 인원으로 측정. 보장 사양 아님 |

| 도메인 | 실제 사용 도메인. 예제 `meet.example.com`은 바꿔야 함 |

회의당 기본 제한은 8명입니다. Python에서 영상 재인코딩을 하므로 인원이 늘수록 CPU 사용량과 송신 트래픽이 빠르게 증가합니다. 설정 숫자만 올려 수용 인원을 확정하지 마세요.

## 2 Docker와 Compose 준비

**아래 명령은 Ubuntu 서버 터미널에서 실행합니다. Windows PowerShell용 명령이 아닙니다.**

### 2.1 기존 환경 확인

```bash
cat /etc/os-release
uname -m
df -h
free -h
docker --version
sudo docker version
sudo docker compose version
```

명령이 없다는 메시지는 해당 도구가 미설치된 경우입니다. `docker compose version`이 정상 표시되면 Compose 설치를 반복하지 않습니다. 이 프로젝트는 공백이 있는 **`docker compose`** 명령을 사용합니다. 옛 `docker-compose` v1만 있는 환경은 Compose 플러그인이 필요합니다.

기존 패키지 확인:

```bash
dpkg -l docker.io docker-ce docker-ce-cli containerd containerd.io runc
```

서로 다른 공급자의 Docker·containerd 패키지를 무작정 섞어 설치하지 마세요. 기존 컨테이너가 있는 서버에서는 패키지 제거가 다른 서비스에 영향을 줄 수 있습니다. 충돌 패키지 정리는 기존 운영 담당자와 상태를 확인한 뒤 수행합니다.

### 2.2 Docker 미설치 Ubuntu 20.04에 focal 저장소 등록

기존 Docker가 없는 서버에서 진행합니다. `/etc/os-release`의 코드명이 `focal`인지 먼저 확인하세요. 다른 Ubuntu 버전에 focal 저장소를 등록하지 않습니다.

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl python3 rsync nano
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
MEETING_ARCH=$(dpkg --print-architecture)
printf 'deb [arch=%s signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu focal stable\n' "$MEETING_ARCH" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
apt-cache policy docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

각 패키지의 `Candidate`가 실제 버전인지 확인합니다. `(none)`이거나 저장소 서명 오류가 나면 다음 설치를 진행하지 말고 패키지 공급 경로를 확인하세요. 다른 Ubuntu 코드명의 패키지를 억지로 설치하지 않습니다. 패키지가 제공되는 환경에서는 다음을 실행합니다.

```bash
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker.service
sudo systemctl enable --now containerd.service
sudo docker version
sudo docker compose version
sudo docker run --rm hello-world
```

이 안내는 Docker 명령 앞에 `sudo`를 붙입니다. 사용자를 Docker 그룹에 추가하는 별도 절차는 필수가 아닙니다. 설치 방식의 기본 구조는 [Docker apt 설치 안내](https://docs.docker.com/engine/install/ubuntu/)를 따르며, focal 사용 조건은 위 1.1절을 적용합니다.

## 3 서버 파일 배치

이하 명령은 새 설치 위치를 **`/opt/moa`**, Compose 프로젝트 이름을 **`moa`**로 통일합니다. 기존 배포에 데이터가 있다면 기존 프로젝트 이름을 유지해야 합니다. 프로젝트 이름이 달라지면 새 DB 볼륨이 만들어질 수 있습니다.

### 3.1 Windows에서 파일 전달

Windows 탐색기와 SFTP 도구로 `화상회의/RelayServer` 폴더를 Ubuntu 계정의 홈 디렉토리에 올려도 됩니다. Windows OpenSSH가 있다면 PowerShell에서 다음처럼 전송할 수 있습니다.

```powershell
scp -r "C:\Users\063\Downloads\교육_1014\화상회의\중계서버" admin@SERVER_IP:/home/admin/
```

`admin`, `SERVER_IP`, `/home/admin/`을 실제 접속 계정과 주소로 바꿉니다. 상위 `화상회의/.venv`는 Windows용이므로 Ubuntu에 복사하지 않습니다. 샘플 시험 데이터가 들어 있는 `data`, 테스트 캡처인 `test-results`, Python 캐시도 신규 운영 데이터로 사용하지 않습니다.

### 3.2 Ubuntu의 배포 위치 준비

다음은 현재 Ubuntu 로그인 계정이 배포 파일을 관리하는 새 설치 예입니다.

```bash
sudo install -d -m 0755 /opt/moa
sudo chown "$(id -un):$(id -gn)" /opt/moa
rsync -a --exclude '.venv' --exclude '__pycache__' --exclude '.pytest_cache' --exclude 'data' --exclude 'test-results' "$HOME/RelayServer/" /opt/moa/
cd /opt/moa
ls server.py Dockerfile compose.yaml .env.example
```

`rsync`의 원본 끝 `/`는 폴더 자체가 아니라 그 안의 내용을 복사한다는 뜻입니다. 서버에 직접 모델을 내려받으려면 전송 시 `models`도 제외할 수 있습니다.

## 4 설정 파일 작성

### 4.1 새 설치의 환경 파일 만들기

```bash
cd /opt/moa
cp -n .env.example .env
nano .env
```

`cp -n`은 이미 있는 `.env`를 덮어쓰지 않습니다. `nano`에서 수정 후 `Ctrl+O`, Enter로 저장하고 `Ctrl+X`로 나옵니다.

```dotenv
DOMAIN=meet.example.com
DB_PATH=/app/data/meetings.db
VOSK_MODEL_PATH=/app/models/vosk-model-small-ko-0.22
MAX_PARTICIPANTS=8
MAX_ROOMS=30
ALLOWED_ORIGINS=
ICE_SERVERS_JSON=[]
```

`DOMAIN`에는 `https://` 없이 실제 도메인만 넣습니다. `DB_PATH`와 `VOSK_MODEL_PATH`는 컨테이너 안의 경로이므로 위 값을 유지합니다. 모든 참여자가 같은 서버가 제공한 화면을 쓰면 `ALLOWED_ORIGINS`는 비워 둡니다.

`ICE_SERVERS_JSON=[]`는 추가 STUN/TURN 서버를 쓰지 않는 초기값입니다. 같은 LAN에서 서버의 미디어 UDP에 직접 도달할 수 있는 시험에 사용할 수 있습니다. 인터넷·공유기·회사망 환경은 6장의 TURN 설정을 함께 검토하세요.

```bash
chmod 600 .env
```

### 4.2 한국어 음성 인식 모델 준비

```bash
cd /opt/moa
python3 scripts/download_model.py
test -f models/vosk-model-small-ko-0.22/am/final.mdl && echo "Korean model files found"
```

공식 모델은 약 82MB 다운로드이며 압축 해제 공간이 추가로 필요합니다. 이미 정상 모델 파일이 있으면 다운로드 스크립트는 다시 받지 않습니다. 모델 설치 후 실행 중인 서버는 재시작해야 모델을 읽습니다. 모델이 없어도 회의와 수동 메모는 가능하지만 자동 회의록은 비활성화됩니다. 모델 출처는 [Vosk 모델 목록](https://alphacephei.com/vosk/models)입니다.

## 5 HTTPS와 방화벽

### 5.1 DNS와 웹 포트

도메인의 DNS가 실제 서버 공인 IP를 가리키도록 설정합니다. 공유기 뒤 서버라면 TCP 80/443을 서버 내부 IP로 전달합니다. 기존 Apache·Nginx·다른 Caddy가 이미 80/443을 사용하고 있는지 확인하세요.

```bash
sudo ss -lntp
getent ahosts meet.example.com
```

Caddy가 공인 인증서를 발급·갱신하려면 도메인과 검증 경로가 실제로 도달 가능해야 합니다. 이 예제는 TCP 80/443을 개방하는 구성이며, 단순 사설 IP 입력만으로 공인 도메인 인증서가 발급되지는 않습니다. [Caddy 자동 HTTPS 안내](https://caddyserver.com/docs/automatic-https).

### 5.2 서비스 포트 표

| 포트 | 용도 | 대상 |
| --- | --- | --- |
| TCP 22 또는 실제 SSH 포트 | 관리용 SSH | 관리자 IP만 허용 권장 |
| TCP 80 | HTTPS 인증·리다이렉트 | 외부 사용자·인증기관 |
| TCP 443 | 웹 화면·API·WebSocket | 회의 참여자 |
| TCP 8000 | 내부 Python HTTP 서버 | 기본 127.0.0.1만 사용. 외부 개방 불필요 |
| 호스트의 임시 UDP 포트 범위 | Python WebRTC 미디어 | 직접 접속할 참여자 및 필요한 TURN 경로 |
| TCP/UDP 3478 | TURN 접속 | TURN을 사용하는 참여자 |
| UDP 49160–49260 | 예제 coturn 릴레이 포트 | TURN을 사용하는 네트워크 경로 |

Python 미디어 포트는 현재 앱에서 별도 범위로 고정하지 않습니다. 실제 서버 범위를 읽습니다.

```bash
cat /proc/sys/net/ipv4/ip_local_port_range
```

예를 들어 출력이 `32768 60999`라면 해당 범위의 UDP 경로를 방화벽·보안 그룹·필요한 NAT 규칙에서 검토합니다. 이 숫자는 예시이며 다른 값을 출력하는 서버에 그대로 적용하지 않습니다.

UFW를 이미 사용하는 서버의 규칙 추가 예:

```bash
sudo ufw status verbose
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
# 실제 범위가 32768~60999일 때만 적용하는 예
sudo ufw allow 32768:60999/udp
# TURN을 사용할 때 추가
sudo ufw allow 3478/tcp
sudo ufw allow 3478/udp
sudo ufw allow 49160:49260/udp
```

UFW가 비활성이면 위 규칙만 추가한다고 방화벽이 활성화되지는 않습니다. 원격 작업 중 `ufw enable`을 실행하기 전에는 실제 SSH 포트 허용 여부부터 확인하세요. 회사망·클라우드 보안 그룹·공유기 포트 전달은 UFW와 별도로 설정해야 합니다. 직접 접속 대역을 제한할 수 있으면 전체 인터넷 대신 그 대역에 한정합니다.

## 6 TURN 설정

HTTPS는 접속되지만 서로 다른 네트워크에서 영상·음성이 안 되는 경우 NAT 또는 UDP 경로 문제가 흔합니다. TURN은 이런 환경의 미디어 중계를 위한 별도 서비스입니다. 앱의 Python 중계 서버와 역할이 다릅니다.

### 6.1 coturn 설정 파일 수정

```bash
cd /opt/moa
openssl rand -hex 24
nano deploy/turnserver.conf
```

위 명령이 출력한 임의 문자열을 TURN 비밀번호로 사용합니다. 예제 설정에서 최소 다음 값을 바꿉니다.

```ini
realm=meet.example.com
user=meeting:생성한_영문숫자_비밀번호
```

서버가 NAT 뒤에 있다면 다음 형식으로 외부/내부 IP를 지정합니다.

```ini
external-ip=203.0.113.10/192.168.0.10
```

위 IP는 설명용입니다. 실제 공인 IP와 서버 내부 IP로 바꿉니다. 서버 자체가 공인 IP를 갖고 있으면 해당 환경에 맞춰 `external-ip` 필요 여부를 확인합니다.

### 6.2 브라우저와 Python 서버에 같은 TURN 정보 전달

`.env`의 `ICE_SERVERS_JSON` 한 줄을 수정합니다.

```dotenv
ICE_SERVERS_JSON=[{"urls":"stun:meet.example.com:3478"},{"urls":"turn:meet.example.com:3478?transport=udp","username":"meeting","credential":"생성한_영문숫자_비밀번호"}]
```

도메인·사용자·비밀번호는 `turnserver.conf`와 일치해야 합니다. JSON 따옴표를 유지하고 여러 줄로 나누지 않습니다. DNS를 CDN 웹 프록시에 연결했다면 웹 HTTPS는 열려도 3478이나 미디어 UDP는 프록시되지 않을 수 있으므로 TURN 주소가 실제 coturn 서버로 도달하도록 구성합니다.

이 예제 coturn은 TLS를 끈 3478 기반 구성입니다. UDP를 차단하는 조직망에서 항상 동작한다고 보장하지 않습니다. 해당 조직망이 허용하는 TURN 전송 방식과 별도 TLS TURN 배포가 필요한지 네트워크 관리자와 확인하세요.

TURN 계정은 회의 참석자에게 연결 설정으로 전달됩니다. 현재의 고정 계정 구성은 소규모 시험용이며, 외부 공개 운영에는 임시 자격 증명 등 운영 보강이 필요합니다. 예제의 `REPLACE_WITH_LONG_RANDOM_PASSWORD`를 그대로 사용하지 않습니다.

## 7 서버 빌드와 실행

### 7.1 설정 문법 확인

```bash
cd /opt/moa
sudo docker compose -p moa config --quiet
```

명령이 종료 코드 0으로 끝나면 Compose 문법과 필요한 변수 해석이 통과한 것입니다. 이것만으로 네트워크 설정이 검증되는 것은 아닙니다. `.env`의 비밀번호가 보이는 전체 `config` 출력을 공개하지 마세요.

### 7.2 사용할 구성 하나로 실행

TURN 없이 직접 연결 시험:

```bash
sudo docker compose -p moa up -d --build
```

TURN도 함께 실행:

```bash
sudo docker compose -p moa --profile turn up -d --build
```

`-d`는 터미널에서 분리해 실행하는 옵션입니다. SSH 창을 닫아도 서버가 유지됩니다. 최초에는 이미지 다운로드와 패키지 설치 시간이 필요합니다. 기본 웹 서비스는 `meeting`, `https`이고 TURN 프로필 사용 시 `turn`이 추가됩니다.

### 7.3 실행 결과 확인

```bash
sudo docker compose -p moa --profile turn ps -a
curl -fsS http://127.0.0.1:8000/api/health
curl -fsS http://127.0.0.1:8000/api/config
sudo docker compose -p moa logs --tail=100 meeting https
```

정상 확인 기준:

- `meeting`이 실행 중이고 잠시 후 `healthy`가 됩니다.
- `/api/health`에서 `{"ok":true}`가 나옵니다.
- 모델을 설치했다면 `/api/config`의 `speech_available`이 `true`입니다.
- 도메인으로 브라우저를 열면 인증서 오류 없이 접속 설정 화면이 보입니다.
- 서버 주소 **연결 확인**이 성공합니다.

TURN 로그는 `sudo docker compose -p moa --profile turn logs --tail=100 turn`으로 확인합니다. `logs -f`로 따라보기 중 `Ctrl+C`는 로그 보기만 끝내며, `-d`로 실행한 서버는 중지하지 않습니다.

## 8 설치 후 실제 회의 시험

1. 서로 다른 PC 두 대에서 HTTPS 주소를 엽니다.
2. 한 PC에서 회의 모드 방을 만들고 다른 PC에 접속 ID를 공유합니다.
3. 양쪽 스피커와 카메라를 켜고 영상을 확인합니다.
4. 방장을 발표자로 두고 마이크를 켜 음성을 확인합니다.
5. 다른 사람에게 발표권을 넘기고 반대 방향 음성을 확인합니다.
6. 발표권이 없는 사람의 음성이 전달되지 않는지 확인합니다.
7. 자동 회의록을 켜고 한국어 문장을 말한 뒤 전사 내용을 확인합니다.
8. 발표자의 문서 창을 공유하고 다른 PC에서 발표자 화면을 봅니다.
9. 화이트보드 그림이 다른 PC에 표시되는지 확인합니다.
10. 회의록을 저장하고 한글 내용을 확인합니다.
11. 인터넷 사용 환경이면 한 PC를 다른 인터넷 회선으로 옮겨 같은 시험을 반복합니다.
12. [자동 시작 안내](04_부팅_자동시작과_장애대응.md)에 따라 재부팅 후 확인합니다.

설정된 최대 인원으로도 시험하고 `sudo docker stats --no-stream`으로 CPU·메모리·네트워크 사용량을 확인합니다. 장치 인식 품질과 외부 네트워크 성능은 실제 환경에서 검증해야 합니다.

## 9 일상 운영 명령

모든 명령은 `/opt/moa`에서 실행하며 새 설치 프로젝트 이름 `moa`를 유지합니다.

| 작업 | 명령 | 영향 |
| --- | --- | --- |
| 상태 확인 | `sudo docker compose -p moa --profile turn ps -a` | 읽기 전용 |
| 서버 로그 | `sudo docker compose -p moa logs --tail=100 meeting` | 읽기 전용 |
| 서버 재시작 | `sudo docker compose -p moa restart meeting` | 진행 중인 모든 방 종료 |
| 설정 반영 | `sudo docker compose -p moa --profile turn up -d --build` | 변경 서비스 재생성 가능. 회의 없는 시간에 실행 |
| 전체 중지 | `sudo docker compose -p moa --profile turn stop` | 기존 컨테이너는 남고 자동 재기동도 수동 재개 전까지 멈춤 |
| 다시 시작 | `sudo docker compose -p moa --profile turn up -d` | 필요한 서비스 실행 |
| 컨테이너 정리 | `sudo docker compose -p moa --profile turn down` | 컨테이너 제거, 이름 있는 볼륨은 기본적으로 유지 |

TURN을 구성하지 않은 환경에서는 실행 명령의 `--profile turn`을 빼세요. `.env` 변경은 단순 `restart`만으로 반영되지 않습니다. `up -d`로 서비스 구성을 다시 적용합니다. Dockerfile 변경이나 패키지 변경에는 `--build`가 필요합니다.

**`down -v`는 DB와 인증서 볼륨까지 삭제할 수 있으므로 일반 중지 명령으로 사용하지 않습니다.** 이 안내에서는 실행할 명령으로 제시하지 않습니다.

## 10 회의록 보관과 백업

### 10.1 데이터 위치

| 환경 | 기록 위치 |
| --- | --- |
| Windows 직접 실행 | `화상회의/RelayServer/data/meetings.db` |
| Docker 새 프로젝트 `moa` | `moa_meeting-data` 볼륨의 `meetings.db` |
| 인증서 | `moa_caddy-data`, `moa_caddy-config` 볼륨 |

컨테이너 이미지 안에 DB를 넣어 보관하지 않습니다. `.env`, `deploy/`, 배포 소스, 모델 또는 모델 재설치 정보도 함께 관리하세요. SQLite는 WAL 모드라서 실행 중인 `meetings.db` 파일만 단순 복사하면 최신 기록이 빠질 수 있습니다.

### 10.2 실행 중 일관된 SQLite 사본 만들기

```bash
cd /opt/moa
mkdir -p backups
sudo docker compose -p moa exec -T meeting python - <<'PY'
import sqlite3
source = sqlite3.connect('/app/data/meetings.db')
target = sqlite3.connect('/app/data/backup-latest.db')
try:
    source.backup(target)
finally:
    target.close()
    source.close()
print('SQLite snapshot ready')
PY
MEETING_BACKUP="./backups/meetings-$(date +%Y%m%d-%H%M%S).db"
sudo docker compose -p moa cp meeting:/app/data/backup-latest.db "$MEETING_BACKUP"
sudo chmod 600 "$MEETING_BACKUP"
```

`backup-latest.db`는 다음 백업 때 갱신되는 임시 스냅샷입니다. 날짜가 붙은 파일을 별도 저장소에도 보관하세요. 백업에는 회의 텍스트가 있으므로 관리자만 읽도록 합니다. 전사 중 아직 DB에 반영되지 않은 발언은 그 시점 스냅샷에 포함되지 않습니다.

### 10.3 종료된 방의 회의록 내보내기

Docker 이미지에는 `scripts/`를 복사하지 않으므로 아래는 **호스트의 Python 3.8 이상**에서 백업 사본을 읽습니다. 데이터 클래스와 기본 SQLite 모듈만 필요합니다.

```bash
cd /opt/moa
sudo python3 scripts/export_minutes.py --db ./backups/선택한백업파일.db --list
sudo python3 scripts/export_minutes.py --db ./backups/선택한백업파일.db --room-id ROOM_ID --output ./backups/종료회의록.md
```

`--list`에서 확인한 긴 내부 `id`를 `ROOM_ID` 자리에 넣습니다. 이는 참석자 초대에 쓰는 12자리 방 접속 ID와 다릅니다. 파일명도 실제 백업 이름으로 바꿔야 합니다. 결과 Markdown을 안전한 방식으로 방장에게 전달하세요.

### 10.4 백업 복원 원칙

복원은 기존 기록을 덮어쓸 수 있으므로 회의가 없는 시간에 진행합니다. 먼저 현재 DB를 위 방법으로 별도 백업하고 `meeting` 서비스를 중지합니다. 선택한 스냅샷의 무결성을 `sqlite3`의 `PRAGMA integrity_check`로 확인한 뒤, `moa_meeting-data` 볼륨에 SQLite 백업 API로 복원합니다. 컨테이너 사용자의 UID/GID는 10001이며 DB 쓰기 권한을 유지해야 합니다.

서버를 다시 시작한 뒤 `/api/health`, `/api/config`, 관리자 내보내기로 기록을 확인합니다. DB를 복원해도 진행 중이던 방이나 화이트보드가 돌아오지는 않습니다. 실제 운영 전에는 별도 시험 볼륨에서 복원 리허설을 수행하세요.

### 11.2 새 Windows PC

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
