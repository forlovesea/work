# v3.2.11 장시간 업로드 장애 보완

## 확인한 원인과 한계

실제 Aging PC의 장애 시점 로그와 큐 DB를 확보하지 않았으므로 최초 연결 단절 원인은 확정하지 않았다. 코드상 아래 문제는 확인하고 회귀 시험했다.

- 실패/대기/사용 안 함 상태에서 상태 버튼이 비활성화되어 장애 기록을 볼 수 없었다.
- 저장 오류 문자열이 정상 저장 후에도 남아 빨간색 상태를 유지했다.
- 512 MiB 큐가 가득 차 신규 snapshot 저장이 막히면, 최신 업로드 성공을 전제로 한 이력 전송도 정지할 수 있었다. 이제 별도 이력 연결에서 성공 ACK를 받은 데이터만 삭제하며 복구한다. 구형 서버가 이력 프로토콜을 지원하지 않으면 데이터는 보존되고 제한된 간격으로 재시도한다.
- 설정 저장 후 UI 스레드에서 큐 건수를 조회했다. DB 대기 또는 오류가 설정 창 닫기에 영향을 줄 수 있어 해당 조회를 제거했다. QSettings 저장 실패도 명시적으로 표시한다. 이것이 현장 저장 무반응의 실제 원인이었는지는 확인하지 못했다.
- 개별 recv 제한시간만으로는 조금씩 도착하는 ACK가 전체 대기를 무한 연장할 수 있어 프레임 전체 제한시간을 적용했다.

## 사용

빨간색 업로드 상태도 클릭할 수 있다. 서버 주소/TLS, 최근 통신 상태, 로컬 저장 오류, 실시간·이력 스레드 상태, 최근 30건의 전송 시각과 결과를 확인한다. `지금 재연결`은 재시도 대기를 초기화한다. 설정 저장은 서버 연결 성공을 의미하지 않는다.

기존 프로그램을 종료하고 새 EXE를 기존 실행 폴더에 배치한다. 기존 profiles와 data 폴더를 유지하고 같은 프로필을 선택해야 기존 설정과 미전송 큐를 이어 사용한다. 이전 목적지의 큐는 설정이 일치할 때만 전송한다.

검증: 모니터링 클라이언트 자동 시험 14건 및 서버 이력 전송 시험 8건 통과. 실패 상태 창 열기, 저장 오류 회복, live ACK 없는 이력 복구, ACK 전체 제한시간, 서버 재접속, 이력의 현재 상태 보존과 ACK 유실 시 재전송 포함. 실제 10일 이상 연속 실행 및 운영 서버 장애 재현 시험은 별도로 필요하다.
