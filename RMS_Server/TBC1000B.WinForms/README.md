# TBC1000B WinForms v3.2.13

## v3.2.13 최초 접속 시 충전 감시 자동 준비

- 최초 유효 장비 데이터 수신 시 기본 충전 임계값을 `min(50A, 총용량 × 충전전류제한(C))`로 자동 초기화합니다. 예: 상한이 30A이면 충전 임계값도 30A로 설정해 바로 감시합니다.
- 방전 50%·5분, 충전 10분 간격은 유지합니다. 별도 버튼 없이 조건 도달 시 실제 CSV 기록을 시작합니다.
- 사용자가 직접 적용한 임계값은 자동 변경하지 않습니다. 상한 정보가 아직 없으면 유효값 수신을 기다리며, 통신 누락을 정상 감시로 표시하지 않습니다.

## v3.2.12 TX/RX LED 잘림 수정

- 표시 배율과 글꼴 크기에 맞춰 TX/RX 컨트롤의 권장 크기를 계산합니다.
- LED 테두리와 안티앨리어싱이 컨트롤 오른쪽 밖으로 나가지 않도록 내부 여백을 확보했습니다.
- 글꼴·DPI 변경 및 크기 변경 시 크기 계산과 다시 그리기를 수행합니다.

## v3.2.11 이벤트 버튼 통합

- 설정 적용과 기록시작을 한 버튼으로 합쳤습니다. 이벤트 영역에는 작업 버튼과 **이벤트 기록중지** 버튼 두 개만 표시됩니다.
- 감시 중에는 **설정 변경 적용**으로 표시하고 값이 바뀐 경우에만 활성화합니다. 중지 상태에서는 **이벤트 기록시작**으로 표시하며 현재 입력값을 검증해 감시를 재개합니다.
- 자동 시작, 제목 옆 진행 상태, 중지 시 설정값 유지 기능은 그대로 동작합니다.

## v3.2.10 자동 감시 상태와 시작·중지

- 설정창이나 설정 적용 버튼을 누르지 않아도 장비 연결 후 기본값으로 이벤트 감시를 시작합니다.
- **충방전 이벤트 기록** 제목 옆에 데이터 대기, 감시 중, 충전/방전 기록 중, 충전 보류, 중지 상태를 표시합니다.
- **이벤트 기록중지**는 진행 이벤트를 사용자 중단으로 기록하고 감시를 중지합니다. 설정값은 유지합니다. 다시 시작하려면 **이벤트 기록시작**을 누릅니다.
- 감시 중에는 중지만, 중지 상태에서는 시작만 활성화됩니다. 사용 이벤트가 하나도 선택되지 않으면 시작 버튼도 비활성화합니다.
- **이벤트 설정 적용**은 변경한 설정이 있을 때만 활성화됩니다. 중지 상태에서 설정을 적용하거나 창을 다시 열어도 자동 재개하지 않습니다. 재실행 시에는 기본 자동 감시로 시작합니다.

## v3.2.9 기본 이벤트 설정

- 충전·방전 이벤트를 기본 사용합니다. 방전은 총용량의 50%·5분, 충전은 50A·10분입니다.
- 장비 연결 후 유효 측정값을 받으면 기본 설정으로 감시합니다. 충전 50A가 장비 상한보다 크면 충전 감시는 보류되며 허용 범위로 변경 후 적용해야 합니다.
- 설정 변경은 **이벤트 설정 적용**을 누릅니다. 재실행하면 위 기본값으로 시작합니다.

## v3.2.8 충전 입력 활성화 수정

- 충전 이벤트 체크 시 임계값과 간격 입력을 즉시 활성화합니다. SOC·전류 수신 여부로 입력을 비활성화하지 않습니다.
- 입력 상한은 총용량·충전전류제한(C)만으로 계산합니다. 일시적인 측정 누락 시 마지막 확인 상한과 입력값을 유지합니다.
- 상한 미확인 상태에서는 임시 입력만 허용하고, 설정 적용 시 최신 측정값 및 실제 충전 상한을 검증합니다.

## v3.2.7 충방전 이벤트 기록

- 운전 데이터 기록 설정의 EPO 항목 아래에 민트색 이벤트 영역을 추가했습니다. 운전 기록 설정은 파란색으로 구분합니다.
- 충전/방전 사용을 개별 체크하고 임계값 및 5·10·15·20·25·30분 간격을 선택한 뒤 **이벤트 설정 적용**을 누릅니다. 운전 Excel 기록을 시작하지 않아도 이벤트 감시는 동작합니다.
- 방전은 총용량(Ah) × 1~90%를 임계전류(A)로 사용합니다. 예: 100Ah × 10% = 10A. 충전은 0.1A 단위이며 상한은 총용량(Ah) × 장비 충전전류제한(C)입니다.
- Rack 전류 양수는 충전, 음수는 방전입니다. 임계전류 이상 관측 시 시작, 선택 간격마다 인터벌, 0A 관측 시 종료를 기록합니다. 임계값 아래로 낮아져도 0A가 되기 전까지 진행합니다. 0A를 건너뛴 방향 전환은 별도 사유로 표시합니다.
- `Operation data record/충방전 이벤트 기록.csv`에 누적 저장합니다. Excel에서 열 수 있는 UTF-8 BOM CSV이며 이벤트ID, 시스템, 종류, 기록구분, 기록·측정·시작시각, 전류, SOC, 총용량, 시작 임계전류, 간격, 사유를 포함합니다.
- 장비 수집이 완료될 때마다 감지합니다. 인터벌은 도달 후 첫 유효 측정값으로 기록하며 과거 SOC를 추정하거나 누락된 간격을 가짜 행으로 채우지 않습니다.
- 통신/측정값 누락, 설정 변경, 앱 종료는 정상 종료 대신 **중단·종료시각 미확정**으로 기록합니다. 중단 행의 SOC는 명시된 측정시각의 마지막 유효 값입니다. CSV 쓰기 실패 시 알림 후 이벤트 감시를 중지합니다.
- 설정창을 닫아도 감시가 계속됩니다. 사용 체크를 해제하고 적용하면 중지됩니다. v3.2.9부터 앱 재실행 시 기본 설정으로 시작하며 장비 연결 후 감시합니다. 장비의 충전 제한 설정 자체는 변경하지 않습니다.

`TBC1000B_감시프로그램_V3.2.3.py`와 `Main_GUI_캡처/Lastest`를 기준으로 진행하는 병렬 포팅 프로젝트입니다. Python 원본은 변경하지 않습니다.

## 빌드

.NET 8 SDK 이상이 설치된 Windows에서:

```powershell
dotnet build .\TBC1000B.WinForms\TBC1000B.WinForms.csproj
dotnet run --project .\TBC1000B.WinForms\TBC1000B.WinForms.csproj
```

저장소 루트에서 빌드 스크립트를 실행할 수도 있습니다. 로컬 `.dotnet` SDK가 있으면 우선 사용하고, 없으면 시스템에 설치된 .NET 8 SDK를 사용합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\TBC1000B.WinForms\build.ps1
```

현재 접속 버튼은 입력된 장비로 실제 SNMP 패킷을 전송합니다. EPO는 개별 또는 전체 확인창에서 실행한 경우에만 전송됩니다. 운전 데이터 기록은 `Operation data record` 폴더에 날짜별 XLSX로 저장됩니다.

```powershell
dotnet run --project .\TBC1000B.WinForms.SmokeTests\TBC1000B.WinForms.SmokeTests.csproj
```

가짜 UDP 장비를 이용해 GET/SET, Trap 및 Huawei MIB 데이터 배율을 검증합니다.

## 릴리스

- `publish/framework-dependent/TBC1000B_Monitor.exe`: 약 0.50MB. 대상 PC에 .NET 8 Desktop Runtime 설치 필요
- `publish/self-contained/TBC1000B_Monitor.exe`: 약 64.9MB. 별도 .NET 설치 없이 실행 가능하며 함께 게시된 네이티브 DLL/Assets 필요

실제 장비 `10.0.0.3:161`에서 읽기 전용 시험으로 sysUpTime, 577개 Huawei OID와 모듈 10개의 전압·전류·상태·SOC·SOH 매핑을 확인했습니다. GETBULK는 응답 유실을 피하기 위해 요청당 10개로 운용합니다.

Master/Slave는 Python 원본과 동일하게 UDP 50000 등록, 5초 heartbeat, 12초 생존 판정, 51000~52000 로컬 Trap 포트 및 장비 IP별 Trap 전달을 사용합니다.

- 이전 Final은 새 빌드 성공 후 `artifacts/single-exe-*/previous-Final`에 보관됩니다.
